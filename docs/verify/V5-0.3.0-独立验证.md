## 2. ① 打桩缺口：整段场景静默消失（这是**验证器**的缺口，不是产品缺陷）

### 2.1 症状

```
FAIL [S7.1] TypeError: app.requestSingleInstanceLock is not a function
             at electron/main.cjs:1820
PASS 67 / FAIL 1 / UNVERIFIED 3 / INFO 4      ← PASS 从 81 掉到 67
```

`electron/main.cjs` 在 task-14 里新增了单实例锁；我的 Electron 打桩没有这个 API，
`require("electron/main.cjs")` 直接抛异常，于是 **S7/S7B 的 14 条检查一起消失**，
摘要里只剩 1 条 FAIL —— 看起来「只坏了一条」，实际是**覆盖被静默删掉**。

### 2.2 修法（两条）

1. 补齐打桩：`app.requestSingleInstanceLock()`、`app.releaseSingleInstanceLock()`、
   `app.setAsDefaultProtocolClient()`、`app.emit()`、`dialog.showMessageBox()`。
2. **加护栏 `S7.0`**：静态扫描 `electron/main.cjs` 里出现的每个 `<命名空间>.<成员>`，
   与打桩逐一对账，缺哪个就报**精确 API 名**；现在输出：

```
PASS  [S7.0] 打桩与 main.cjs 的 Electron API 面一致（不会再因缺 API 而崩掉整段场景）
      main.cjs 用到 25 个 <命名空间>.<成员>，打桩全部具备
```

> `S7.0` 第一版自己有 bug：把 `session.defaultSession` 误报成缺失（我只查了 `session.<成员>`，
> 没查 `session.defaultSession.<成员>` 这条链）。**是它自己当场报出来的**，已改成链式检查。
> 记录在 §8。

### 2.3 并把「静默丢覆盖」本身变成 FAIL（`S7-coverage`）

`withCoverageGuard(label, expectedIds, body)`：跑完场景后核对「本该出现的检查 id」是否**全部被报告**
（PASS/FAIL/UNVERIFIED 都算），缺失的显式报成 FAIL；场景中途抛异常也会先记一条 `<label>-crash`。

**为什么这条最重要**：这一轮真实的失败模式不是「报了假通过」，而是
**「检查干脆不见了，摘要看起来只坏了一条」**。静默减少覆盖比报错危险得多 ——
报错会有人修，覆盖消失**没人会发现**。这条护栏现在是 `S7/S9` 的默认包装。

## 3. ② 通道保真：0.3.0 的核心新行为，此前在 E2E 里**完全看不见**

### 3.1 驱动侧的缺口（C1 发现，我确认）

`00` §6.13⑧ 要求「本地桥转交前设 `"local-bridge"`」；`receive.ts:367`：

```ts
if (landingPreference === "inbox" && isExternalDeliveryChannel(getImportChannelContext().channel))
  return enqueuePending(envelope, hashes);
```

而 `verify-e2e.cjs` 此前**从不调用** `setImportChannelContext()`，所有投递都跑在模块默认
`"in-app"` 上 → `isExternalDeliveryChannel("in-app") === false` → 强制 `pending` 分支从不进入。
**于是「默认设置 → 外部导入进收件箱」这条 0.3.0 的主行为，在端到端脚本里没有任何一条断点在测它。**

### 3.2 补上的断点（全部为「我已跑绿」）

```

      getImportLandingPreference()="inbox"、默认通道="in-app"、overwriteEnabled=false
PASS [S9.1] 默认设置 + local-bridge 投递 → pending、path=null、无新 .md、收件箱恰好 1 条
      status=pending inboxId=20260929T161215-verify-c（匹配 /^\d{8}T\d{6}-.{8}$/=true）
      path=null 新增 .md=0 收件箱=1 笔记数 0 → 0
PASS [S9.2] 同 importId 重投幂等：收件箱仍恰好 1 条、磁盘仍 0 个新增 .md
      重投回执 status=deduped（严格 deduped —— 命中第 1 步幂等索引） 收件箱=1 新增 .md=0
```

或把 `deeplink.cjs` 一起复制到临时目录；顺带把「读不到摘要」与「护栏没变红」分成两种失败消息

### 6.3 变异验证（`--mutate-copy=main`，只改内存、不写盘）

即：**改一处文案，断言立刻红**（并精确报出「哪个码、哪个产地、两边各是什么」）。

### 6.4 收窄口径（Lead 裁定，已按此实现）

| 情形 | 处理 | 依据 |
| --- | --- | --- |
| 文档格混有「给实现者的注解」（如 `IMP-4011` 文案格里的 `（overwrite 降级与 skip 情形不提示…）`） | 取第一个 `（`/`(` **之前**的部分当基准；**并记 INFO**（不静默跳过） | 同 `C-6d`/`C-6e` 口径 |
| 一个格子覆盖多种分支的码（`IMP-4011`） | 不逐字比（`DOC_MULTI_CASE_CODES`） | Lead 裁定 |
| `IMP-4008` 反引号 | **不放宽，继续红**，直到两边改齐 | Lead 裁定：反引号是字面字符，会显示给用户 |

> 「截断注解」这条只在「原样比不过、截断后完全相同」时才生效 ——
> 这样它**不会**把真的漂移洗成通过（`收件箱已满（500 条）…` 这类**文案自带括号**的值仍按原样比）。

### 6.5 「同一个值的多个产地」——可复用结论

> **凡是「一个语义值被复制到 N 处」的地方，护栏必须覆盖全部 N 处，否则第 N+1 次改动必然漂移。**

本轮三个实例，全部由同一条规律造成：

1. `IMP-4006`：桥表 vs 主进程 `NO_WINDOW_ERROR()`（`C-6c` 只盖桥）→ 已由 `C-6f` 覆盖。
2. `bridgeStatusPayload`：字段被「重建」时丢掉一半（`address`/`error`/`portRange`/`lastPairing`…）
   —— 写的人只保证自己那几个字段，**没有断言全部字段**（见 `V4` 的 D-02）。
3. `IMP-4008`：6 个产地里 3 个带反引号 —— 没有任何断言比过它们。

**反之的正面例子**：`C-6c`（桥 ↔ 文档）与 `C-6f`（全产地 ↔ 文档）都在跑，且**都有变异验证**。

## 7. 可复用护栏模式（这一轮的真正产出）

### 7.1 `S7.0` 静态 API 面比对：**生产代码长出新 API，打桩必须跟着长**

```js
electronApiGaps(stub)  // 扫描 main.cjs 里每个 <命名空间>.<成员>（含 a.b.c 链），与打桩逐一对账
```
价值：打桩缺一个 API → 整段场景**静默消失**（就是 §2 那个 81→67）。
现在缺哪个 API 会被**按名字**报出来，而不是等到 `require` 崩了才发现。

### 7.2 `S7-coverage` 覆盖守卫：**未报告 = FAIL**

```js
withCoverageGuard("S7", EXPECTED_S7, () => scenario7Body(env))
```
- 场景跑完核对「expected ids 是否全部被报告」（PASS/FAIL/UNVERIFIED 都算「报告过」）；
- 中途抛异常 → 先记 `<label>-crash`，把缺失 id 全部报成 FAIL；
- **核心原则**：**静默减少覆盖比报错危险** —— 报错有人修，覆盖消失没人发现。

### 7.3 断言必须「红得起来」：**每条新护栏都自带变异验证**

本轮的 4 处变异验证（全部真实跑过、两种输出都留档）：

| 护栏 | 变异方式 | 是否如期变红 |
| --- | --- | --- |
| `S7.9`（接线侧） | 内存里删掉 `src/App.tsx` 的那一行 | ✅ 变红 |
| `S7.10`（行为侧） | 同一链路声明 vs 不声明通道 | ✅ `pending` vs `created` |
| `C-6f`（多产地） | `--mutate-copy=main` 改一个字 | ✅ 变红并报出精确位置 |
| `S8.2`/`C-6c`（上一轮） | 同前 | ✅ |

### 7.4 断言「比增量、比范围」而不是「比绝对值」

见 §8 的两个自曝 bug：新工作区**自带 1 个 `.md`**，收件箱条目**自己也有 `body.md`** ——
「绝对值」断言会莫名其妙地红/绿。
