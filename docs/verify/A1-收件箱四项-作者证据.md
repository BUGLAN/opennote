## 3. 未做 / 已知边界

- **`failed` 条目的 7 天保留期没有动**（`02` §5.8.3 的契约）。用户对「失败记录有没有用」的疑问，
  本轮只落到「界面上不再给它单独一栏」，**不擅自改保留期**；要「失败即自动清理」是契约级改动，需另行裁定。
- **`跳过这次` 的点击接线没有单测**：仓库的 `vitest.config.ts` 是 `environment: "node"`、没有 jsdom，
  首屏护栏只能走 `react-dom/server`（effect 不跑、点击模拟不了）。这条由 §1 的真机步骤覆盖
  （点 → 确认框 → 删除 → OPFS 实读目录消失 → 面板仍在）；**数据层**的 `discardInbox` 本来就有单测。
- **失败条目在默认视图里看不到**：这是「待确认 = 只有 pending/committing」的直接结果。入库失败时
  toast 仍会说出原因，条目在「全部」里可重试或丢弃（`S5` 语义未变）。
- **`跳过这次` 仍要过一次确认框**（用户答复「先确认再删除」）：丢弃不可恢复，`FR-29` / `02` §6.12②
  要求确认框如实说明不可恢复。
- 浏览器核对用的是 **OPFS 浏览器笔记本**（无桌面端 watcher 时走 30 秒轮询 + 显式 `refreshInbox()`），
  桌面端 `node` 后端与 watcher 路径本轮没有重跑；两者共用同一份渲染层代码。
