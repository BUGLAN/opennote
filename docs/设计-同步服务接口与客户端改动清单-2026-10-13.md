## 0. 先说结论

- **服务端要做的事只有 8 件**（§1），核心是「一个文件夹 + 一个索引 + 一条变更流水 + 一个 SSE 通知」。
- **技术栈（已定）**：**Node 22 + TypeScript + Hono/Fastify + SQLite + SSE，与客户端同仓**（§2）。
  理由：协议是我们自己的，最大的风险是两端类型漂移；同仓 TS 能共享 contract 与 `assertSafeRelative` 路径规则。
  CouchDB 作为「不想写代码」的备选保留（§2 表格 C1）。
- **客户端改动集中在同步层与数据层**：新增 `src/sync/*`，改 `library.ts` / `workspaces.ts` / `App.tsx` / 状态栏 / 两处 CSP；**编辑器、Markdown 渲染、剪藏协议、样式完全不动**（§5）。
- 先做 **P0（正确性前置）**，它和后端选谁无关，现在就能做。

## 1. 服务端要做什么（职责边界）

**要做的 8 件事**

1. 存文件字节（就是磁盘上的普通文件夹，便于 `rsync` 备份）。
2. 列树：`path → {hash, size, rev}` 的**紧凑投影**（不能把正文带上）。
3. 单文件读写 + **乐观锁**（`If-Match` 对不上返回 409）。
4. 逻辑删除（tombstone），并保留「谁在什么时候删的」。
5. **单调递增的 cursor/seq** + `changes?since=` 增量列表。
6. **SSE 推送**：告诉在线客户端「有新版本」，事件里可以带变化的 path。
7. 鉴权（Bearer token，建议每设备一个，便于吊销）+ CORS（网页端要用）。
8. 原子写 + 崩溃自愈（临时文件 + rename，重启时对账一次）。

**明确不做的**：不解析 Markdown、不做搜索、不做用户系统、不做 CRDT、不做冲突自动合并（冲突由客户端三方 diff 决定，服务端只保证「不丢版本」）。

## 2. 技术栈选型

| 方案 | 栈 | 服务端代码量 | 什么时候选 |
| --- | --- | --- | --- |
| **C1（借用现成协议）** | Docker + CouchDB 3.x + Caddy/nginx（TLS） | **0**（只写客户端） | 不想拥有协议；接受服务端是数据库形态、内存占用最高 |
| **C4-A（已定 ✅）** | **Node 22 + TypeScript + Hono（或 Fastify）+ SQLite + SSE**，与客户端**同仓** | 小（约数百行 + 测试） | **本项目的选择**：要在两个端之间共享契约与路径规则（见下） |
| C4-B | **Bun + TypeScript**（内置 `Bun.serve`、`bun:sqlite`、SSE） | 更小，单文件部署 | 想要「一个文件丢上 VPS 就跑」，愿意引入第二个运行时 |
| C4-C | **Go 1.22+**（`net/http` + `modernc.org/sqlite`） | 小，静态单二进制，内存最低 | 最看重运维省心，不在乎协议类型要写两遍 |
| 不推荐 | Rust / Deno / Serverless | —— | 对这个小服务都过重，或与「一台 VPS」的场景不匹配 |

### 为什么推荐 Node + TypeScript（与客户端同仓）

1. **协议是我们要拥有的东西，它最大的风险是「两端类型漂移」。** 同仓 + 一个共享 contract 文件可以消掉一整类 bug。
   这个仓库**已有先例**：`src/clip-web/contract.ts` 就是「扩展 ↔ 应用」的共享契约类型。
2. **路径安全规则可以共用**：`src/fs/paths.ts` 的 `assertSafeRelative()`（`paths.ts:21-33`，拒绝绝对路径、`..`、NTFS ADS 冒号）
   是纯函数。服务端 import 同一个函数，就不会出现「客户端拒绝、服务端接受」的裂缝——这是自研协议最容易出的洞。
3. **测试同构**：仓库已经是 Vitest（`environment: "node"`）。provider 的契约测试可以对着
   「内存实现」和「真实服务」各跑一遍，不需要引入第二套测试栈。
4. **仓库已有同类先例**：`electron/bridge.cjs` 就是一个绑 `127.0.0.1` 的极小 HTTP 服务（零新依赖 + 令牌校验），
   说明「在仓库里自带一个小 HTTP 服务」不是异类。
5. **部署够简单**：systemd 一条 `node server/index.js`，或 Docker；Caddy 自动 TLS。

**Go 的唯一硬优势**是单二进制与内存；但代价是**协议类型和路径规则要在两边各写一遍**，正是我们最想避免的漂移点。

**服务端需要的 Node 版本比客户端高**：客户端要求 `node >=20.19`（`package.json:engines`），
服务端建议 **Node 22+**（`node:sqlite` 可用，避免 `better-sqlite3` 这类原生依赖；若不想用实验 API，用 `better-sqlite3` 也行）。
构建上要确保 Vite **不把 `server/` 打进前端产物**（`tsconfig.json` 的 include 与 Vite 入口分开放）。

## 3. 服务端 HTTP 契约（v1）

```text
鉴权：Authorization: Bearer <token>        （建议每设备一个 token）
Base：https://sync.example.com/v1

GET    /v1/health                          -> { ok, version }
GET    /v1/tree                            -> { cursor, files: [{ path, hash, size }] }
                                            （紧凑投影，不含正文；支持 limit 分页）
GET    /v1/changes?since=<cursor>          -> { cursor, changes: [{ path, op: add|update|delete }] }
GET    /v1/file?path=<urlenc>              -> 200 bytes / 404
PUT    /v1/file?path=<urlenc>              -> 200/201 { hash }  |  409 { current: { hash, rev } }  |  412
          Header: If-Match: <hash>            （缺省 = 允许新建；对不上 = 409）
DELETE /v1/file?path=<urlenc>              -> 204  |  409  |  410
          Header: If-Match: <hash>
GET    /v1/events                          -> text/event-stream
          data: {"cursor":N,"paths":["a.md",...]}     （只当「来拉了」的信号，不携带内容）
```

四个刻意的设计点：

1. **`path` 走查询参数，不走 URL 路径段**：笔记路径里有 `/`，`encodeURIComponent` 会把 `/` 变成 `%2F`，
   而部分反代/CDN 会把它还原或拒绝。放 query 里最稳。服务端仍要用 `assertSafeRelative` 校验。
2. **`If-Match` 用内容哈希，不用 ETag**：哈希是客户端已有的概念（`LocalFile.hash`），
   语义比服务端自定的 ETag 清楚；对不上返回 409 + 当前哈希，客户端就能只对这一篇重做决策。
3. **`changes?since=` 允许「cursor 过期」**：客户端传的 cursor 太旧（流水已裁剪）时，
   返回 `{ resync: true }`，客户端退化成**全树比对**——而 `planPush`/`planPull` 本来就是全树比对的，天然支持。
4. **SSE 只发「来拉了」**：不在事件里塞内容，客户端收到就置 dirty 跑一次正常同步。
   这样断线重连、补漏、乱序都不需要第二套逻辑。

### 存储布局

```text
/data/
├── vault/            <- 真实文件夹，和本地目录同构（备份 = rsync 这个目录）
├── index.sqlite      <- files(path, hash, size, rev, deleted, at) + changes(seq, path, op, at) + tokens
└── (日志)
```

- **写入**：临时文件 → `fsync` → `rename` 覆盖；然后在一个 SQLite 事务里更新 index 并追加一条 change。
  崩溃在两步之间 → 启动时做一次**对账扫描**（或靠客户端哈希比对自愈）。
- **rev**：每个 path 单调递增，只在内容真变时 +1（避免「碰一下就算改」）。
- **CORS**：`Access-Control-Allow-Origin` 放行 PWA 的 origin，允许头含 `Authorization, If-Match, Content-Type`；
  **必须正确处理 `OPTIONS` 预检**——`PUT` + `If-Match` 一定会触发预检。
- **限额**：单文件与单请求体上限（默认如 32 MB，可配），防止小鸡被打满。
- **TLS**：交给 Caddy（自动证书）或 nginx；服务本身只听 `127.0.0.1`。
- **备份**：`rsync vault/` + SQLite 的在线备份（WAL checkpoint 或 `.backup`）。

## 7. 待定与风险

1. **服务端鉴权模型**：单 token vs 每设备 token（推荐后者，便于吊销）；令牌存哈希，别存明文。
2. **CORS 细节**：`PUT` + `If-Match` 必然触发预检；`OPTIONS` 响应与 `Access-Control-Allow-Headers` 要对齐。
   桌面端没有这个问题（主进程不是浏览器）。
3. **路径边界**：服务端必须复用 `assertSafeRelative`；另外注意 **macOS 的 NFD 与 Linux 的 NFC**
   会造成「看起来一样、字节不一样」的路径——客户端已有大小写与路径规则，服务端要对齐同一套。
4. **主进程代理的收窄**：只允许「配置好的 base URL + 相对路径」，**不能**做成通用 `fetch(url)`——
   否则一次 XSS 就能借它绕过 CSP 把笔记外发。这是本次改动里唯一新增的安全面，值得单独 review。
5. **构建隔离**：确保 `server/` 不进前端产物、不进 Electron 包。
6. **`.gitignore` 支持**：别自己写解析器（见共存文档 §10.6）。
