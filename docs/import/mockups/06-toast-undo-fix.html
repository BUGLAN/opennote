入库提示修复原型仅设计 · 未进实现

病灶来自一张夜读主题的截图：入库 toast 的长标题把药丸撑成两行板砖，「撤销」被 flex 挤压成竖排两个字，整块亮色浮在暗页上，看起来像一枚不属于当前主题的外来通知。取色核实：药丸底 #eae3d7 就是夜读的 --ink——颜色其实一直来自令牌（DESIGN.md 规定的反色药丸），真正坏掉的是布局：消息没有省略保护、动作按钮没有禁缩。本页给出修复设计：四条规则全部落在既有令牌与既有类名上，新增令牌数为 0。默认夜读主题，可用顶部切换器核验 5 套调色板 × 4 套强调色。

二、修复方案（四条规则，全部既有零件）

R1 消息恒单行.toast__msg 加 min-width:0 + 溢出三件套（overflow hidden / text-overflow ellipsis / white-space nowrap）。标题过长尾部省略。与全项目行模板的「文字列三件套」约定一致（DESIGN.md §列表与行）；UI-05 的定位是「极短、可撤销、不抢焦点」，单行就是它的形状。
R2 动作恒宽.toast__action 加 flex:none + white-space:nowrap。两个汉字的按钮宽度恒定，任何文案长度下不再收缩、不再换行——竖排 bug 的一行 CSS 硬修复。
R3 次级说明独立成行只有降级撤销出现：.toast__body 列向包住 .toast__msg + .toast__sub（--fs-xs、opacity .78、同样单行省略），主文案保持「已从网页剪藏：{标题}。」完整可读。小字出现即代表撤销力度变弱，属必须告知的语义差别（UI-05 补充）。
R4 几何一字不动99px 圆角、--shadow-2、rise 220ms --ease-out、padding 8px 14px、--fs-md 全部照旧；max-width 补一条响应式护栏 min(420px, 100vw − 32px)，沿用对话框的 32px 边距惯例——桌面端无感，PWA 窄窗口不再横向溢出。
R5 颜色零改动--ink 底 / --paper 字的反色药丸是全项目反馈语言（.busy / .storage-notice 同构）。换底色会丢掉「一眼认出这是通知」的识别度，也违背 DESIGN.md 的语义状态规定。状态仍旧只用两档：中性墨色药丸 = 成功，强调色药丸 = 失败。

四、否决的反例（展示理由，不进实现）

反例 1 · 底色跟随纸面
--paper-2 底 + --rule-strong 边：「通知」变成「一张纸片」
已从网页剪藏：《中文排版指北》。
否决
否决理由夜读里它需要描边才可见，且与 .dialog / .menu 无法区分；反色药丸的识别度恰恰来自「页面是纸、通知是墨」的反转。强调色语义也不允许再引入第三种表面。
反例 2 · 允许两行（-webkit-line-clamp:2）
多给一行标题：高度跳变 + 板砖感仍在
已导入笔记：ComfyUI 图片内嵌工作流：作者说明摘录（Qwen-Image 2.1 / MiniMax H3）
否决
否决理由同一标题短一则一行、长则两行，堆叠时高度参差；用户感知的「板砖」没有消失，只是矮了一点。降级说明已经用 .toast__sub 承担了「第二行」的正当场景。
反例 3 · 动作做成 .btn
描边按钮：破坏药丸的单一形状
已从网页剪藏：《中文排版指北》。
否决
否决理由UI-05 / S2 明文规定动作「不加背景块，保持药丸的单一形状」；下划线文字 + hover 透明度 .78 是药丸动作的既定手感（.toast__action 原样保留）。
