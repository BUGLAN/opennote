入库提示、冲突与失败

导入的失败方式是打断写作，所以这一页是最需要设计的一块。三条原则：成功用中性墨色药丸，失败用强调色药丸并配一句能读懂的中文，错误不抖动、不变红、不闪烁。所有 toast 文案逐字取自 PRD 冻结清单。

焦点不移动到 toast——用户正在打字时抢焦点是严重打断（原则 P1）。动作按钮需要 pointer-events: auto 才可点（.toast-root 本身是 pointer-events: none）。
Ctrl/⌘ + Z不绑定为撤销导入：编辑器撤销有自己的语义，混淆两者会造成误删。
两档撤销改变既有笔记内容的操作（append / overwrite）若回执 canRollback=false，toast 多一行小字「内容已合并进已有笔记，撤销会把整篇移入回收站。」——小字出现即代表撤销力度变弱，属必须告知的语义差别。新建（new）永远是完整回退，不加小字。
不提示的两种情况① deduped: true（同一幂等键重复投递）一律静默——第二次本来就什么都没发生；② conflict: skip 返回 200 + skipped，按成功处理，最多一行「已存在同名笔记，按设置跳过」。
时长带动作的提示 10 秒（FR-25 冻结值，实现必须显式传 duration；现有 toast.ts 的 action 分支默认是 6000ms，不满足要求），不带动作的 2600ms。

动效约定：哪里动、哪里不动

动toast 出现 rise 220ms；错误块出现 rise 220ms；状态芯片「启动中」圆点 pulse 1.8s（成功后立刻停）；收件箱条目被消耗后 fade 120ms。
不动错误不抖动（no shake）、不闪红、不扫光；列表不逐条入场；数字徽标不弹跳；按钮 hover 不做位移或缩放；加载不用整屏遮罩。
降级prefers-reduced-motion 下动画与过渡降为 0.01ms（本文件已内联）；「启动中」不能只靠脉冲，必须同时有文字。
屏幕阅读器toast 用 role="status" 而非 alert，避免打断屏幕阅读器正在朗读的内容；多条时为 aria-live="polite"。

UI-13 · opennote:// 唤起确认（FR-64 / P1）

URL scheme 可以被任意网页、任意本地程序触发，所以必须弹一次确认再入库——静默入库等于给了一个免鉴权的写入入口（00 §6.8④：只做短载荷 ≤4 KiB 与收件箱领取）。默认焦点落在次要按钮上，回车不应该直接写入。
