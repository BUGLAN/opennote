导入收件箱

只有开启「先进入收件箱」模式、或某次导入需要人工判断时，用户才会来到这里。骨架沿用「历史版本」对话框的两栏（.history），条目沿用文件树的树行手感。示例数据含一条 example.com 网页剪藏、一条来自 Claude Code 的导入、一条正文为空的失败项、一条同 URL 重复剪藏。

丢弃确认标题「丢弃这条导入？」正文「「{标题}」还没入库，丢弃后不会进入回收站。」确认「丢弃」（btn--danger），取消「留下」。按 FR-29 冻结语义：丢弃只删待确认条目，回收站条目数不变——所以确认框必须如实说明不可恢复，不能写「可以再找回来」。
条目的 5 个状态pending（左侧 2px 强调色竖条）/ committing（「正在写入…」+ 旋转环，两个按钮都禁用）/ committed（「已入库 · {相对时间}」，保留 24 小时，这期间撤销仍有意义）/ failed（code 的中文文案 + 「还有 {n} 天」，保留 7 天）/ discarded（「已丢弃」，无「恢复」）。
条目的字段客户端（插件 / 命令行 / AI 助手 / 分享 / 手动放入，取 entry.client.name + version）、落点（entry.target.folder 为空时显示「笔记本根目录」）、附件数与合计大小、冲突建议（只渲染 new / append / skip，不渲染 overwrite）、attempts 与 updatedAt。
外部投递标记投递方不是应用时，标题右侧加一个 --fs-xs --ink-3 的「外部」小字（不加重色边框），让用户知道这条不是自己在应用里点的。
列表上限500 条；达到上限时列表顶部一行「收件箱已满（500 条），请先处理一些条目。」不做自动淘汰，避免静默丢内容。
剪藏时间用 entry.source.capturedAt（本地时区），不要用目录名里的 UTC 时间戳。

键盘可达性与无障碍

打开时焦点落在左列表第一个条目（不是对话框本身）；aria-label="导入收件箱"。
列表↑/↓ 移动，Home/End 到首尾，Enter = 入库当前条目，Esc 关闭（Modal 已实现）。
筛选role="radiogroup" + role="radio"，←/→ 切换；切换后焦点回到当前条目，被筛掉则落到第一条。
屏幕阅读器列表容器 aria-label="收件箱条目，共 {n} 条"；当前条目 aria-current="true"；每条可访问名 = 「{标题}，来自 {站点}，{剪藏时间}，{客户端}」。
Destructive 键Backspace / Delete 不绑定任何破坏性操作，避免误删。
窄屏 ≤720px切单栏：左列表变成横向可滚动的条目条（每条 min-width 180px），详情在下方，底部动作区 sticky。再窄则改为「条目 → 点开详情」两级。
焦点陷阱现有 Modal 实现了 Esc 关闭但未见焦点陷阱；三个新模态层需补齐「打开移入焦点、Tab 循环在层内、关闭归还触发元素」（规范 10.3）。

中文排版指北

来源：example.com · 2026-09-21 15:04

先说结论：中文排版里最容易被忽略的不是字体，而是行内标点与外文之间的空隙。
许多编辑器把「中英混排」当成字体问题处理，实际上是间距与断行的问题。

S1 默认站点名是可点击链接（--accent），点击用系统浏览器打开原 URL（shell.openExternal），不在应用内开网页；站点名与时间之间用「 · 」分隔。
S2 站点名缺失用 URL 的 host 兜底；仍拿不到则整行退化为「来源：无来源」，并且不渲染链接。
S3 只有 URL 没有时间「来源：example.com」——省掉分隔符，不显示「· null」。
S4 hover / 聚焦链接下划线出现；--accent-line 焦点环；整行不做背景高亮，避免行高跳动。
S5 长站点名站点名 max-width 18ch + 省略号，title 属性给完整值；时间不换行。
S6 窄屏 ≤720px时间另起一行，站点名单独一行（--fs-xs），不横向滚动。
S7 从未剪藏这一行完全不存在（不占位、不留空隙）——手写笔记不该看到「来源：无」。
S8 来源链接已失效不影响渲染；点击后由系统浏览器自己报错，应用不拦截、不预检。
可访问性整行是 <p> 而不是按钮；链接是真正的 <a>（去掉默认跳转、改为 openExternal），Enter 可打开；屏幕阅读器读成「来源：example.com，2026-09-21 15:04」，所以时间不能写成纯图标。
三处都显示「来源」但目的不同：UI-11 是阅读时的溯源、UI-03 是入库前的确认、UI-04/R6 是事后的审计。因此尺寸与位置各不相同，只共用同一份数据。
