## 3. 能力一句话与三层架构

**一句话**：让用户把网页上选中的片段、整篇文章、或 AI 会话里产出的内容，**经由接口**存进自己的 OpenNote 笔记本——内容始终留在本机，不经任何服务器。

```
L0 导入信封   opennote.import/v1        ← 与传输无关的唯一契约（字段名已锁定）
      ↑ 由谁产生
L1 传输通道   本地桥(127.0.0.1) · CLI · MCP · Skill · opennote:// · 页面内桥(postMessage) · 收件箱目录 · 剪贴板
      ↓ 交给谁
L2 应用内接收  落点决策 · 去重/幂等 · 冲突处理 · 可撤销 · 通知渲染层重扫
```

分层的关键约束：**信封不决定落点**（安全要求），**文件名由应用侧生成**（客户端无法预知），**L1 任一通道都必须经过 L2 的同一套校验**。

## 4. 已锁定的关键决策（改动需回到 `00` 号走裁定流程）

1. **信封字段**：`spec` / `importId` / `title` / `body` / `source{url,title,site,author,publishedAt,capturedAt,selection}` / `target{folder,notePath}` / `conflict` / `tags[]` / `assets[]{name,mime,dataBase64}` / `client{name,version}`。
2. **front-matter 8 键（固定顺序）**：`source → source_title → source_site → author → published_at → captured_at → tags → opennote_import_id`；其中**只有 `tags` 会被应用解析**，其余为惰性元数据。
3. **标题必须写成正文的 `# H1`**（`deriveTitle()` 只认正文首个标题/非空行，不认 front-matter）。
4. **落点冲突默认值**：同名 → `new`（自动 ` 2` 后缀）；同 URL → `append`；用户正在编辑该笔记 → 永不自动覆盖。
5. **默认入库模式**：**直接入库 + 可撤销提示**；设置里可改为「先进入收件箱等待确认」。
6. **`overwrite` 需四道闸门同时满足**：客户端显式请求 + **仅桌面版本地桥通道** + 用户在进阶开关里显式开启（默认关闭）+ 写入前留下可回退前像；否则降级为 `new` 并回警告。非目标：**永不默认覆盖、永不由自动化客户端覆盖、覆盖前必有可回退副本**。
7. **去重判定链（有序四分支）**：同 `importId` → 幂等（返回首次落点）→ 同 URL 且正文哈希相同 → 回执 `duplicate`、不追加 → 同 URL 但哈希不同 → 选区 `append` / 整页进收件箱 → 仅哈希相同但 URL 不同 → 视为两条独立笔记。
8. **可恢复性**：`append` / `overwrite` 写入前留**逐字节前像**（`.opennote/import-preimages/`，**不放在 `history/` 之下**，避免与快照保留策略耦合）+ 导入日志（`.opennote/import-log.json`，上限 500 条，与前像同源清理）；历史快照有约 3 分钟节流，**不得**用快照代替前像承诺可回退。
9. **重复剪藏的唯一规范文案**：`已在笔记中（未重复入库）。`——**应用内不弹 toast**，由插件 popup / CLI stderr / 收件箱条目**内联**显示，并进「最近导入」与导入日志。
10. **收件箱 `discarded` 不进回收站**：用户主动丢弃 = 条目与内容**立即清理、不可恢复**；保留期只管队列（`committed` 24 小时 / `failed` 7 天 / `pending`·`committing` 不设期限）。

## 5. 通道与平台真相（不夸大）

| 通道 | 桌面版 (Electron) | Chrome/Edge 网页版 (FSA) | 其它浏览器 (OPFS) | 关键前提 |
| --- | --- | --- | --- | --- |
| 本地桥 HTTP（默认关闭） | **P0** | 不可用（CSP `connect-src 'self'`，页面无法 fetch 本地桥） | 同左 | 需应用运行并开启接口、完成配对 |
| CLI（`opennote clip`） | **P0** | 不支持 | 不支持 | **Opennote 必须正在运行**（桥生命周期跟随窗口） |
| MCP / Skill（AI 场景） | **P1** | 不支持 | 不支持 | 同上；不运行时必须以明确错误码失败，不得假成功 |
| `opennote://`（短载荷） | **P1** | 不支持 | 不支持 | 载荷 ≤4 KiB，正文不入 URL |
| 页面内桥（postMessage） | 不用（有本地桥） | **P0** | **P1 且绑定 D12 门禁** | 需要 Opennote 页面在场 |
| 收件箱目录 `.opennote/inbox/` | **P0**（应用内接收与确认）／**P1**（外部程序直接投递） | 不支持 | 不支持 | 外部投递属本机信任边界的固有属性 |
| 剪贴板手动粘贴 | 有 | 有 | 有 | 永远的降级兜底路径 |

**如实说明的三条限制**：①桌面桥只在应用运行时存在（「AI 帮我把这篇存一下」的前提是 Opennote 开着）；②FSA/OPFS 没有 `realpath`，符号链接/联接的越界防护弱于桌面版；③移动端不在 P0 验收范围内（`iOS Safari` 与 `Android Chromium` 差异按 `01` §4 如实呈现），只有降级提示。

## 7. 本阶段的边界与非目标

- **零代码**：本目录不含任何实现，`src/**`、`electron/**` 未被本团队改动（Lead 已用检索断言：本特性相关标识符 0 命中）。
- **不做服务端**：无账号、无遥测、无云端解析，内容不出本机；不实现「只给一个 URL 由应用抓网页」。
- **不改变既有导入语义**：手动导入（设置 · 文件 →「导入文件或 zip」）保持原样，本需求是新增通道而非替换；单文件仍有既有的 32 MiB 上限。
- **不引入新设计令牌**：设计稿只使用 `src/styles/tokens.css` 现有变量（评审复算：6 份稿的 68 个 hex 与 `tokens.css` 完全同集合，新增 0）。
- **已知待实现事项**（评审 §10.3 登记）：模态层需补焦点陷阱与焦点归还、toast 动作按钮需 `pointer-events: auto`、插件需复用 `tokens.css`、状态栏新项在窄窗口的隐藏规则。
