## 0. 本文档怎么用

1. **视觉只有一个来源**：`src/styles/tokens.css`。本文档不定义新的配色/间距/圆角/阴影/动效体系；第 6 节给出「新组件 → 现有变量」的逐条映射，**新增令牌数为 0**。
   - **行号说明**：本文档引用的 `src/**` 行号**截至撰写时**（HEAD `7ea0661` 加当时的工作区）有效。工作区另有一条并发修改产品代码的线（D01–D38 缺陷修复），行号会漂移；核对时请以**类名与令牌名**为准，行号只作定位线索。
2. **界面用稳定编号**：`UI-01 … UI-10`，每个界面下再分状态（`UI-03/S4` 这种写法）。01 号的需求条目（`FR-xx`）与 02 号的错误码在第 10 节做对照，评审可逐行核对。
3. **文案逐字给出**：第 4 节中所有带「」的字符串都是**可直接复制进代码**的中文文案。术语只用 00 号简报第 5 节那套词（剪藏 / 导入信封 / 通道 / 本地桥 / 收件箱 / 入库 / 来源信息 / 落点 / 幂等键）。
4. **设计稿是设计交付物，不是产品代码**：`docs/import/mockups/*.html` 不放进 `src/`、不 import 任何项目模块、无构建步骤，双击 `file://` 即可打开。
5. **实现侧约束**（会影响视觉还原，故写在这里）：浏览器插件 popup 是**独立文档**，无法 `@import` 应用的 `src/styles/tokens.css`。实现时必须把 `tokens.css` 整份**复制**进插件目录并在两处保持同源（例如构建期做一次内容哈希比对），而不是手抄数值——手抄是这套「纸与墨」体系最常见的漂移来源。

## 1. 设计原则

导入功能的失败方式不是「不好看」，而是**打断写作**。以下 5 条按优先级排列，出现取舍时上位原则优先。

### P1 · 内容先落地，界面后出声

写作时人的注意力是最稀缺资源。外部导入的默认路径必须是「零确认」：内容已经写成磁盘上的 `.md`，界面只用一条**可撤销**的提示告知结果（00 号简报 §6.4 锁定的「直接入库 + 可撤销提示」），而不是弹一个需要阅读和点击的对话框。

- 具体体现：`UI-05` 用现有 toast（`src/components/Overlays.tsx:224`），不用模态框；`UI-06`（冲突决策）只在**真的需要人来判断**时出现。
- 反面写法（明确禁止）：入库成功弹一个「导入成功」模态框配一个「确定」按钮。

### P2 · 新界面必须像「同一个应用」

导入是新增能力，不是新增产品。所有新界面只允许由**现有组件类名**拼装：`.dialog` / `.setting` / `.segmented` / `.switch` / `.swatch` / `.cmd` / `.tree__row` / `.choice` / `.toast` / `.statusbar__item` / `.empty`。任何一个界面如果无法用这些零件拼出来，说明设计走偏了（见第 2 节）。

- 具体体现：设置里的「导入与接口」是一个 `SettingRow` 列表（`src/components/AppDialogs.tsx:411`），不是一张自成一体的卡片面板；收件箱沿用「历史版本」对话框的两栏骨架（`src/styles/app.css:1367`）。

### P3 · 纸与墨的克制：状态用文字说，不靠颜色喊

现有令牌里**没有**成功绿 / 警告黄 / 失败红这套语义色——危险操作一律用 `--accent`（`.btn--danger` 是 `color: var(--accent)`，`src/styles/base.css:201`；`.toast--danger` 是 `background: var(--accent)`，`src/styles/app.css:1521`）。新界面沿用这一点：

- 「成功」= 中性墨色药丸（`.toast`，`--ink` 底 / `--paper` 字）。
- 「失败 / 需要处理」= 强调色药丸（`.toast--danger`）+ **一句能读懂的中文**。
- 连接状态不用红绿灯三色，改用 **圆点的填充方式**（实心 / 空心 / 脉冲 / 描边）+ 文字（见 `UI-04/S1`）。这样在「夜读」「砚池」暗色主题下不会出现某个绿色被背景吃掉的问题。

### P4 · 外部的东西进来时，用户必须随时能知道「它从哪来、去了哪」

剪藏和 AI 导入都是**外部写入**，比用户自己敲字更需要可追溯性。每个界面都要能回答三个问题：来源（哪篇网页 / 哪个客户端）、落点（存到哪个目录的哪篇笔记）、结果（成功 / 追加 / 进收件箱 / 失败）。

- 具体体现：`UI-01` 的落点与来源信息在提交前就可见；`UI-03` 每条收件箱条目都显示来源站点、剪藏时间、客户端名、落点；`UI-04` 有「最近导入」列表。

### P5 · 如实描述能力差异，不做「都支持」的界面

三种文件系统后端能力不等（00 号简报 §2 第 2 条）：只有 Electron 桌面版能「外部进程直接落盘」。所以：

- 插件 popup 在**网页版**场景下必须显示「没有本地接口」的明确状态，而不是转圈（`UI-01/S9`）。
- 设置里的「导入与接口」在网页版是**可见但禁用**的，并说明原因（`UI-04/S9`），而不是整个消失——消失会让人以为功能不存在。
- 移动端在 P0 没有通道，界面上不出现任何入口（不做假入口）。

### UI-02 · 页面内选区浮标

**定位**：选中文字后，在选区上方浮出一个极小的动作条，让「选中 → 剪藏」不经过工具栏。

**布局结构**：单个 `--radius:99px` 的药丸，高 26px，`--ink` 底 / `--paper` 字（与 `.toast` 完全同构，`app.css:1507-1519`），`--shadow-3`；内容为 `記` 印章微缩（14px 方块）+ 文字 `剪藏`；右侧一个 1px `--rule-strong` 竖分隔 + 一个仅图标按钮「整页」（`title="剪藏整页正文"`）。

- 位置：选区包围盒上方 `--s2`，水平居中；上方空间不足时翻转到选区下方。
- 出现/消失：`rise 120ms var(--ease-out)`，消失 `fade 120ms`。不做弹跳、不做缩放过冲。
- 触发：`mouseup` 且选区 ≥ 1 个非空字符；选区被折叠或点击浮标外区域即消失。

**状态表**（`UI-02/S1…S5`，共 5 条）

| 编号 | 状态 | 表现 |
| --- | --- | --- |
| `S1` | 默认 | 药丸淡入；「剪藏」文字 `--paper`；`記` 方块 `--accent` 底 |
| `S2` | hover（「剪藏」） | 药丸底从 `--ink` 提到 `color-mix(in srgb, var(--ink) 88%, var(--paper))`；`--dur-fast` |
| `S3` | 聚焦 | `:focus-visible` 焦点环画在药丸内侧（`outline-offset: -2px`），因为药丸贴着文字，外环会盖住内容 |
| `S4` | 加载 | 「剪藏」替换为 12px 旋转环，药丸宽度不变（`min-width` 固定） |
| `S5` | 错误 | 药丸底变 `--accent`、字 `--accent-ink`（即 `.toast--danger` 的反色关系），文案换成 `本地接口未开启`，2.4 秒后自动消失 |

**交互流程**：选中 → 浮标出现 → 点「剪藏」→ 直接投递（不打开 popup）→ 成功时药丸短暂变为「已剪藏」再消失；失败时按 `S5`，并在 1 次点击后把 popup 打开并停在 `UI-01/S9` 的错误态（一次性把用户送到能解决问题的地方）。

**键盘可达性**：浮标**不进入 Tab 顺序**（它是鼠标增强，键盘用户走 popup 与快捷键）。理由：把浮标纳入焦点顺序会让页面本身的 Tab 顺序被插件污染，属于对宿主页面的侵入。插件提供 `Ctrl/⌘ + Shift + S` 作为键盘等价路径（需在 manifest 的 `commands` 里声明，属实现事项）。

1. 桥返回成功 → 立即写盘 → 立即弹 toast（**不等**界面重扫完成，`FR-35` 的重扫在后台进行）。
2. 用户点「撤销」→ `FR-26`：**新建的这次导入 → 删除本次新建的文件**（不是移入回收站）；**追加 → 把笔记恢复到追加前（逐字节一致）** → 弹一条 2600ms 的 `已撤销这次导入。`
3. 10 秒内没点 → toast 消失。用户后来反悔 → 走 `FR-27`：回收站（侧栏「其他 → 回收站」，`Sidebar.tsx:351-357`）。所以「撤销」按钮从 UI 上消失**不等于**内容不可恢复，这条必须写进 02 号文档的语义里。

**键盘可达性**

- toast 容器 `role="status"`（现有实现，`Overlays.tsx:230`），多条时为 `aria-live="polite"`，屏幕阅读器朗读文案。
- 动作按钮**可通过 `Tab` 到达**（`toast-root` 有 `pointer-events: none`，需要给动作按钮单独 `pointer-events: auto`；这是现有实现的注意点，属实现事项）。
- `Ctrl/⌘ + Z` **不**绑定为撤销导入：编辑器里的撤销有它自己的语义，混淆两者会造成误删。撤销只通过 toast 按钮与回收站两条路径。
- 焦点**不移动**到 toast：用户正在打字时焦点被抢走是严重打断（原则 P1）。

#### UI-03 补充 · 收件箱条目的 5 个状态与保留期（按 `02` §5.8.2–5.8.3）

`state.status` 是 5 个枚举，**每一个都要能画出来**（不能只画 `pending` 与 `failed`）：

| `status` | 条目左侧竖线 | 次级文字 | 可做的动作 |
| --- | --- | --- | --- |
| `pending` | `--accent` | 什么都不加（这是常态） | `入库` · `丢弃` |
| `committing` | `--accent` | `正在写入…` + 12px 旋转环 | `入库` 与 `丢弃` 均禁用 |
| `committed` | `--rule-strong` | `已入库 · {相对时间}`（条目会保留 24 小时再清除，这段时间里「撤销」仍有意义） | `查看`（打开那条笔记） |
| `failed` | `--accent` | `{上表对应 code 的中文文案}` + `还有 {n} 天`（`failed` 保留 7 天） | `重试` · `放弃` · `查看原因` |
| `discarded` | `--paper-4` | `已丢弃`（`--ink-3`）；`丢弃` 不进回收站（`FR-29`），所以这里**没有**「恢复」 | 无 |

其余必须显示的字段（用 `02` 的字段名，不要自造）：`entry.client.name` + `version`（枚举 `chrome-extension` / `cli` / `mcp` / `share-target` / `manual` / `other`，右侧显示为「插件 / 命令行 / AI 助手 / 分享 / 手动放入」）、`entry.target.folder`（`null` 或空时显示 `笔记本根目录`）、`entry.assets.length` 与合计大小、`entry.conflict`（**只渲染 `new` / `append` / `skip`，不渲染 `overwrite`**——收件箱通道一律忽略它）、`state.attempts` 与 `state.updatedAt`。

**「本条目由外部投递」标记**：投递方不是应用时，标题右侧加一个 `--fs-xs` `--ink-3` 的「外部」小字（不加重色边框），让用户知道这条不是自己在应用里点的，减少「谁动了我的笔记」的困惑。条目 key 用目录名 `<UTC 时间戳>-<importId 前 8 位>`（**不要**把目录名里的 UTC 时间当剪藏时间显示，显示用 `entry.source.capturedAt`）。列表总量上限 **500 条**，达到上限时列表顶部一行 `--fs-sm` `--ink-2`：`收件箱已满（500 条），请先处理一些条目。`——不做自动淘汰，避免静默丢内容。

#### UI-05 补充 · 撤销的两种能力必须在界面上可区分（`00` §6.7④）

`append` / `overwrite` 入库前**必须**记录可回退前像，但前像可能不可得（例如既有笔记已被外部修改、或前像写失败）。回执/导入日志要能表达「这次操作是否可逐字节回退」，界面据此分成两档，**不合并成一句「撤销」了事**：

| 档 | 回执 | 文案 |
| --- | --- | --- |
| 可逐字节回退 | `canRollback: true` | 标准 `已从网页剪藏：{标题}。` + `撤销`；撤销后弹 `已撤销这次导入。`（2600ms） |
| 只能降级 | `canRollback: false` | `已从网页剪藏：{标题}。` + 次级说明 `内容已合并进已有笔记，撤销会把整篇移入回收站。` + `撤销`；撤销后弹 `已把《{标题}》移入回收站，可以再找回来。` |

新建（`new`）情形永远是第一档（撤销 = 删除本次新建的文件，`FR-26`），所以不需要次级说明——**只有改变既有笔记内容的操作才可能出现降级**。这一区分同时解释了为什么 `UI-05` 的 toast 有时带一行小字、有时不带：小字出现即代表「撤销的力度比你想的弱」，属于必须告知的语义差别，不是视觉装饰。

| 编号 | 状态 | 表现 |
| --- | --- | --- |
| `S1` | toast · 危险态 | `.toast--danger`：`--accent` 底 / `--accent-ink` 字；动作文字同色下划线；`rise 220ms` |

### UI-12 · 页面内桥状态与文件夹授权提示（`FR-39`：**FSA = P0 / OPFS = P1 + D12 门禁**）

**分期（`00` §6.11① 裁定，三份文档统一口径）**：

| 平台 | 后端 | 分期 | 启用条件 |
| --- | --- | --- | --- |
| Chrome / Edge 网页版 | **FSA**（页面持有目录句柄） | **P0** | 页面在场即可用；属 `00` §6.7③ 的 P0 判定标准之内 |
| 其它浏览器（Firefox 等） | **OPFS**（浏览器私有存储） | **P1** | **D12 门禁**：必须在 D12 的修复**提交且有测试覆盖**之后才允许启用（理由：OPFS 的「导入文件夹覆盖同名」与页面内桥的写入语义同源，D12 未修时启用等于把覆盖风险放大到自动化通道） |

**定位**：这两种场景下插件**不能**请求本地桥——网页版的 CSP 指令是 `connect-src 'self'`（`vite.config.ts:166`）与 `default-src 'self'`（`vite.config.ts:158`），桌面版注入的是 `default-src 'none'`（`electron/main.cjs:53`）与 `connect-src 'self' file:`（`electron/main.cjs:58`）——**行号截至撰写时，引用以指令名 + 值为准**。因此页面内桥**只能**通过当前打开的 Opennote 页面用 `postMessage` 转交，不能直连本地接口。所以需要一个「我正被谁连着」的状态指示，以及「文件夹授权掉了」的提示态。

**位置**：设置 · 文件的「导入与接口」区块里，`R3 本地接口` 上方插入一行 `R0 当前平台通道`（桌面版不显示这一行，桌面版显示 R3）。

| 状态 | 表现 |
| --- | --- |
| `S1` **FSA 网页版（P0）** · 页面在场、等待投递 | `R0` 值：`网页版通道已就绪，剪藏工具可以把内容发送到这个标签页。` 状态芯片 `已就绪`（实心圆点）；底部 `--fs-xs` `--ink-3`：`保持这个标签页打开，剪藏才能送进来。` |
| `S2` 刚收到一次投递 | 芯片短暂变为 `刚刚收到 1 条`（`rise` 220ms，4 秒后还原）；不弹 toast（投递本身已经在应用内触发入库提示，两处都弹会重复） |
| `S3` 文件夹授权失效（US-06） | 应用内 toast（`--accent` 底）：`Opennote 需要重新授权这个文件夹，本次剪藏已暂存，授权后会自动入库。` 动作 `重新授权`；点击后走既有的目录选择授权流程，授权完成再补投，提示变为 `已重新授权，正在补投…` |
| `S4` 插件未配对 | 与 `UI-01/S6` 同一份配对流程；设置面板只显示 `还没有已配对的客户端。`，配对在插件侧完成 |
| `S5` **OPFS（P1）· 门禁未过** | `R0` 是**禁用态**（`opacity: .5`）且文案必须表达「**尚未开放**」而不是「不支持」：`这个浏览器里的笔记本暂时还不能接收剪藏，正在做最后的适配。` + 次级一行 `--fs-xs` `--ink-3`：`需要等浏览器端的覆盖保护修好之后才能开启。` **不写「不支持」**——能力存在，只是门禁未放行；两者的用户预期完全不同 | 
| `S6` OPFS · 门禁过后（P1 放行） | 与 `S1`~`S3` 同款，但 `R0` 说明换成 `浏览器私有存储，外部程序无法直接写入；请保持本页打开。`（`FR-56` 的如实告知） |
| `S7` iOS Safari / 移动端 | `R0` 不出现；P0 不显示任何通道入口。P1 只在 Android Chromium 的分享面板里出现入口（`FR-65`），iOS 给降级路径：`手机上暂时不能直接剪藏到 Opennote。可以复制正文，在 Opennote 里新建笔记粘贴。` |

## 7. 微交互与动效

**总则**：动效只用来解释「东西从哪来、到哪去」，不用来吸引注意。全部复用现有 `@keyframes`（`rise` / `fade` / `pop` / `pulse`，`base.css:281-314`、`app.css:668-676`）与三档时长（120 / 220 / 460ms）。

### 7.1 哪里动

| 位置 | 动画 | 时长/缓动 | 说明 |
| --- | --- | --- | --- |
| 插件 popup 打开 | 无 | — | popup 由浏览器负责出现，额外动画会显得卡 |
| 插件 popup 内分段切换 | 预览卡内容 `fade` | `--dur-fast` `--ease` | 只淡入新内容，不做横向滑动 |

| 收件箱条目被消耗后移除 | `fade` | `--dur-fast` | 120ms 后从列表移除，不做高度塌陷动画（避免列表跳动） |
| 状态芯片切换（未开启 → 启动中 → 已开启） | 圆点 `pulse` | 1.8s `--ease` 无限 | 只在「启动中」使用，成功后立刻停止（连续脉冲会持续抢注意力） |

| toast 里的动作点击后的反馈 | 无动画，就地换文案（`复制` → `已复制`） | 120ms 颜色过渡 | 见 `UI-04/S7` |
| 首次引导展开安装步骤 | 无高度动画，直接出现 | — | 高度过渡会引起文字重排抖动，得不偿失 |
| 首次引导首屏（作为整屏空状态时） | `rise` | `--dur-slow` `--ease-out` | 只在整屏空状态使用，与 `.empty__inner` 一致 |

### 7.2 哪里**不**动（明确禁止）

1. **列表行不逐条入场**：收件箱条目、最近导入列表不做 stagger 延迟动画。导入是后台行为，列表跳动会打断写作。
2. **数字徽标不弹跳**：待确认计数从 0 变 1 时不做缩放/弹跳。
3. **错误不抖动**（no shake）、不闪红。
4. **按钮 hover 不做位移/缩放**：现有点击反馈只有 `.icon-btn:active { transform: translateY(.5px) }`（`base.css:154-156`），新按钮沿用这一级，不引入 `scale`。
5. **加载态不用整屏遮罩**：任何导入操作都不阻塞写作区；加载只发生在被操作的那个控件上。
6. **不使用 `@keyframes sheen` 之类的扫光效果**：项目里有这个 keyframe（`base.css:316-323`），但导入界面不使用——扫光属于「SaaS 仪表盘」语言。

| 主题 | 前景 / 背景 | 对比度 | 达标情况 | 本规范的使用限制 |
| --- | --- | --- | --- | --- |
| 素笺 | `--ink` `#221d17` / `--paper` `#fbf8f3` | ≈ 14.5:1 | AAA | 无限制 |
| 素笺 | `--ink-2` `#5c5347` / `--paper` | ≈ 7.1:1 | AAA | 无限制 |
| 素笺 | `--ink-3` `#97897a` / `--paper` | ≈ 3.2:1 | **低于 AA 4.5:1**，仅大字达标 | **禁止**用它承载按钮文字、错误句、状态文字；只用于时间戳、补充说明这类「不看也不影响操作」的信息 |

| 夜读 | `--ink` `#eae3d7` / `--paper` `#14120f` | ≈ 14.8:1 | AAA | 无限制 |
| 夜读 | `--ink-2` `#b0a796` / `--paper` | ≈ 7.9:1 | AAA | 无限制 |

**结论**：这套令牌在两种主题下的主要文本都达标；`--ink-3` 在两种主题下都略低于 AA，这是**现有系统的既有限制**（不是本功能引入的）。本设计规范的做法是**限制其用途**，而不是新增一个更深的提示色令牌——因为那会改变整个应用（包括现有界面）的观感，超出本需求范围。如果项目后续要修，应作为独立的可访问性任务统一处理。

### 8.2 焦点

- 全部可聚焦元素沿用 `:focus-visible`（`base.css:95-99`），**一致不自定义**；唯一的例外是 `UI-02` 的浮标（`outline-offset: -2px`），因为外环会盖住页面文字。
- 所有模态层（收件箱、冲突、首次引导）必须「焦点进入 → 焦点被困住 → 关闭后归还」。现有 `Modal` 已实现 `Esc` 关闭（`Overlays.tsx:110-119`），**焦点困住与归还属于实现需要补齐的部分**（现有 `Modal` 未见焦点陷阱代码），已在第 10 节列为交付给实现的明确要求。
- 焦点顺序必须与视觉顺序一致；`UI-03` 的两栏在 DOM 中「列表在前、详情在后」，与视觉一致。

### 8.3 `prefers-reduced-motion`

- 沿用 `base.css:329-337` 的全局降级（动画 0.01ms、过渡 0.01ms）。
- 插件 popup 与设计稿**各自内联同一段降级规则**（插件是独立文档，拿不到应用的 CSS）。
- 降级后必须仍然可用：`UI-01/S1` 的骨架屏在降级后仍然显示（它是静态的 `--paper-3` 色块，不依赖动画）；`UI-04/S3` 的「启动中」在降级后**不能只靠脉冲**，因此该状态必须同时有文字「正在启动本地接口…」（已经如此，见 `UI-04/S3`）。

### 8.4 屏幕阅读器

| 界面 | 要求 |
| --- | --- |
| 全部 toast | `role="status"` + `aria-live="polite"`（现有 `.toast` 已是 `role="status"`，`Overlays.tsx:230`）；危险 toast 用 `role="status"` 而非 `alert`，避免打断屏幕阅读器正在朗读的内容 |
| 全部对话框 | `role="dialog"` + `aria-modal="true"` + `aria-label`（现有 `Modal` 已实现，`Overlays.tsx:126-129`） |
| 连接状态芯片 | `role="status" aria-live="polite"`，状态变化朗读一次 |
| 收件箱列表 | 容器 `aria-label="收件箱条目，共 {n} 条"`；当前条目 `aria-current="true"`；每条按钮的可访问名 = 「{标题}，来自 {站点}，{剪藏时间}，{客户端}」 |
| 令牌块 | `role="group" aria-label="访问令牌"`；令牌文本节点带 `aria-readonly`，并提供一个仅屏幕阅读器可见的完整令牌（`.sr-only`，`base.css:269-278`），因为视觉省略中间会让朗读无意义 |
| 只读图标 | `aria-hidden="true"`（装饰性），按钮用 `aria-label` 或 `title` 提供名称；插件浮标的图标按钮 `aria-label="剪藏整页正文"` |
| 分段控件 | `role="radiogroup"` + `role="radio"` + `aria-checked`，`←/→` 切换 |
| 冲突选项 | `role="radiogroup"` + `role="radio"`，每项 `aria-describedby` 指向自己的说明句 |
| 步骤列表 | `<ol class="steps">`，序号由 CSS 的 `counter` 渲染时必须在 DOM 中保留文本序号（不用 `list-style: none` 抹掉语义） |
| 加载态 | 加载中的按钮 `aria-busy="true"`；整块加载（如 `UI-03/S3`）用 `role="status"` 播报「正在读取收件箱」 |

## 11. 对 00 号简报的异议

**异议 1（建议变更，非阻塞）：00 号简报 §6.4 的「直接入库 + 可撤销提示」在**网页版**无法成立，界面需要一条明确的降级路径。**

00 号简报 §6.4 锁定的默认值是「直接入库 + 应用内可撤销提示」，其前提是「外部写入能到达应用」。但 §2 第 2 条同时确认：只有 Electron 桌面版能「无需页面在场即可写磁盘」；FSA 需要页面持有句柄授权，OPFS 外部进程访问不到。因此：

- 桌面版：`FR-13` 的默认值成立，`UI-05` 的撤销提示可用。
- Chrome/Edge 网页版：外部导入**根本无法到达**应用，除非 Opennote 窗口正开着且通过页面内桥（`postMessage`）投递。
- 其它浏览器的 OPFS 笔记本：同上，且更弱。

**建议**：在 01 号文档里把 §6.4 的表述补成「默认直接入库 + 可撤销提示（**桌面版**）；网页版在同窗口在场时走页面内桥，不在场时明确告知不可用」。界面侧我已经按这个事实画：`UI-01/S9`、`UI-04/S9`、`UI-07` 的 `IMP-1006` 三处都把「当前平台不能直连本地接口」当作**一等状态**显示，而不是转圈或假装成功。这一条如果不补，评审时会出现「同一个默认值在四个平台上语义不同」的漏洞。
