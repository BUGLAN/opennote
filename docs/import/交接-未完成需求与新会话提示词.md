## 四、未完成需求（按优先级）

### A【新里程碑 · 最大】网页版剪藏页（用户原话）
> 「网页版 opennote 打开这条，能够编辑，支持移动到收件箱或者说其他目录」
> 「先编辑，确认后再入库」
> 「这样保证渲染的效果，代码是现成的，工作量也更小」

**为什么是这个方案**：扩展的 host_permissions 只有 10 条 ⇒ 普通网站靠工具栏点击授予的
`activeTab`；**一旦别的标签成为活动标签，原标签就失去 active ⇒ 后台拿不到它的 url**。
所以「在插件的页面里回头再读源页面」在权限模型上走不通。正解是：**扩展在还有授权时
（popup 里）把内容交给本地接口，页面只负责编辑与确认。**

**已冻结的接口契约（不许改字段/形状，要改先改 02 号文档）**：
```
POST /v1/clip/stage
  鉴权 Authorization: Bearer <token>（扩展带，与 /v1/import 同一个令牌）
  请求体 { spec:"opennote.clip/v1", url, title, body, selection, tags[],
           source{site,author,publishedAt}, assets[] }
  响应   { ok:true, stageId:"<接口生成的不透明 id>", expiresAt:<ms>,
           openUrl:"http://127.0.0.1:<port>/clip/<stageId>?k=<不可猜的键>" }

GET  /clip/<stageId>?k=…                 → 返回页面 HTML（Vite 构建产物），页面内注入 { port, stageId, k }
GET  /v1/clip/folders?stageId=…&k=…      → { folders:["", "归档", "剪藏/技术", …] }
POST /v1/clip/commit { stageId, k, title, body, folder } → 返回已有的回执（ImportResult 同形状）
```
四条已定的决定：
- **`stageId` 由接口生成**（不许用扩展的 importId）—— 暂存是接口的状态，一个产地；
- **`openUrl` 由接口返回，扩展不许自己拼** —— 端口是 8787–8796 里选出来的；
- **页面拿 `k`（不可猜、随条目过期），不拿桥的长期令牌** —— 页面永不持有长期凭据；
- **`folder` 省略/空 = 进收件箱（㉕ 不变）；非空 = 必须是已存在的目录**（不自动创建）；
- **`commit` 内部必须复用已有的入库通路**（收件箱 → 接收端），**不许另造第二条写路径**。

**扩展侧只做两件事**：① `POST /v1/clip/stage`；② `chrome.tabs.create({ url: openUrl })`。
失败就如实报（**不打开页面** + popup 显示原因），不许静默。
**接口侧就绪前，popup 里的 `CLIP_WEB_READY` 保持 `false`**（它现在就是 `false`，入口按钮因此不渲染）。

**建议顺序（每步可独立验）**：
1. 接口侧：静态服务 + `POST /v1/clip/stage` + `GET /clip/<id>?k=`（页面先只做**只读显示**，
   证明「扩展 → 暂存 → 服务 → 页面读到」这条线通）
2. 页面侧：Vite 新入口，**复用应用的 src/styles/tokens.css 与 markdown 渲染器**（这才是「渲染一致」的来源）
3. 编辑 + 落点选择（复用 `POST /v1/import` 的 `target.folder`）
4. 扩展侧接通 + **删掉插件里的 `extension/src/clip/clip.html`**（及其测试与构建产物）

## 五、今天的纪律清单（**请原样保留**，它们都是花代价换来的）
- **不给猜测当修复**：先排除「是不是我的测试写错了」，再建仪器，最后把判读表交出来等外部证据。
- **NO_EFFECT ≠ MISSED，这条也适用于检查器自己。**
- **恒绿的检查比没有检查更坏** —— 它会让下一个人以为这条覆盖了。
- **判据误报一次，就等于教别人忽略它一次。**
- **修实例 ≠ 修类**（`normalizeUrl` 修了、`highlights` 漏了 —— 于是有了类级自由变量检查）。
- **配对只守一半 = 没守**（死路由、restoreNote 的反方向、两个发送方）。
- **注释也是标签**（`U-8` 范围与标题不符、`C-10s` 逃生口含「不再」被自己放行）。
- **守卫的价值不在它被写出来，而在它被证明能红** —— 今天兑现 6 次：
  扫 `node --test` 输出（TAP 重包装，永不触发）、`process.exit(2)` 被归一成 1、异步 stderr 被
  `process.exit` 截断、import 插入没落地、`.building` 跑前清理缺失、`$R`/`$r` 大小写撞车。
- **观测本身会改变被测对象** —— 用健康请求做就绪探测，给 mock 多发一次请求，把按请求计数判定的
  `rate-limit` 用例打偏（**3/3 稳定复现，不是 flake**）。改成 TCP 连接探测。
- **判据要盯契约/意图，不要盯实现的字面** —— 写死变量名/调用形状会让它在**产品正确**时变红；
  漏字符/范围过宽会让它在**产品错误**时变绿。两端都是「你以为在比对的东西，与实际比对的不是同一个」。
- **锚点/证据必须锚在被改的那个文件上**，落地后必须回读确认；**判据的细节必须与被判对象逐字一致**。
- **探针不许改变它所观测的东西**（`tabs.create` 关掉 action popup ⇒ 后续 evaluate 超时，
  那个 FAIL 是工具造成的，不是产品回归）。
- **改动脚本/工具后必须 `node --check`** —— 落地自检的下一层：不仅「改到了」，还要「还是能跑的」。
- **写而不读 = 假开关**；**没有超时的等待态在一次性界面里 = 永久白屏**。
- **不迁移旧数据**；**一个方向修了、另一个方向没修，就等于没修**。
