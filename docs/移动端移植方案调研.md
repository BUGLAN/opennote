# Opennote 移动端移植方案调研(安卓 / iOS)

> 调研日期:2026-10-08 · 结论:**可以移植,且 Opennote 属于"最容易移植"的一类架构**。真正的工作量在移动端 UX 打磨与上架流程,不在代码移植本身。

## 一、结论先行

Opennote 是纯前端 React 19 + Vite 8 + CodeMirror 6 应用,Electron 只是薄壳,文件系统已抽象为多后端(`src/fs/` 下有 `nodeBackend` / `fsa` / `opfs` 三套实现)。这意味着:**UI 与业务逻辑 100% 复用,只需给 `src/fs/types.ts` 的接口新增一个移动端实现**。业界同类产品(Obsidian 移动端)正是走这条路线。

## 二、浏览器 API 现状(决定各方案成本)

| 能力 | iOS Safari | Android Chrome | 对 Opennote 的影响 |
| --- | --- | --- | --- |
| `showDirectoryPicker`(File System Access) | ❌ 完全不支持 | ✅ 154 起刚支持 | iOS 上现有 `fsa.ts` 检测自动失效,走回退 |
| OPFS(`storage.getDirectory`) | ✅ 15.2+ | ✅ | **现有 `opfs.ts` 后端在两端移动浏览器都能直接跑** |
| IndexedDB | ✅ | ✅ | 现有 `idb` 元数据存储不受影响 |
| PWA 安装 | ✅ 16.4+ 加入主屏幕 | ✅ 成熟 | 已有 vite-plugin-pwa,基础现成 |

数据来源:[caniuse: showDirectoryPicker](https://caniuse.com/mdn-api_window_showdirectorypicker) · [caniuse: OPFS getDirectory](https://caniuse.com/mdn-api_storagemanager_getdirectory)

关键点:`src/desktop/bridge.ts` 注释明确一切都是可选的——纯浏览器环境回退到 FSA 或 OPFS。**在手机浏览器/WebView 里,应用今天就能运行**,差别只在"笔记是不是磁盘上的任意文件夹"这个核心卖点。

## 三、三条路线对比

### 路线 A:PWA 直接当移动版用(零成本起步)

现有 Web 版已是 PWA。Android 基本开箱即用;iOS 加入主屏幕后可用。

- ✅ 零原生代码、零上架流程
- ⚠️ iOS 的坑:**普通 Safari 网站的脚本可写存储(含 IndexedDB)在 7 天不交互后会被系统清除**(Didomi 文档),加入主屏幕后豁免([iPhone PWA 指南](https://deepclick.com/zh-CN/resources/blog/pwa-on-iphone))
- ⚠️ 无法访问真实文件夹,笔记锁在 OPFS 里,导出/同步要靠应用内功能
- 来源:[Didomi:Apple implements 7-day cap on script-writable storage](https://docs.didomi.io/releases-and-announcements/announcements/apple-implements-7-day-cap-on-script-writable-storage)

### 路线 B:Capacitor 打包(推荐,主流正解)

[Capacitor 官方明确支持"直接加入任何现有现代 JS 项目"](https://capacitorjs.com/docs/)——把 `vite build` 产物装进原生 WebView 壳。

- ✅ 新增一个 `capacitorBackend.ts` 实现 `FSCore` 接口即可,用官方 [@capacitor/filesystem](https://capacitorjs.com/docs/apis/filesystem)(提供 readFile/writeFile/readdir/mkdir 等 Node 风格 API)
- ✅ iOS 上配两个 plist 键(`UIFileSharingEnabled` + `LSSupportsOpeningDocumentsInPlace`),**笔记就能以纯文件形式出现在系统"文件"App 里**,最大程度保住"plain files"的产品理念
- ✅ 完整支持 App Store / Google Play 分发、深链、推送、更新
- ✅ **Obsidian 移动端就是这条架构**(Capacitor + WebView + CodeMirror 6),证明编辑器层在移动端可行([架构参考](https://deepwiki.com/obsidianmd/obsidian-help/1.1-application-architecture-and-data-storage))
- ⚠️ iOS 构建需要 Mac + Xcode;Apple 开发者账号 $99/年,Google Play $25 一次性

### 路线 C:Tauri 2 移动端(备选)

[Tauri 2 已支持 iOS/Android](https://v2.tauri.app/start/),用系统 WebView、包体小(<600KB 级别)、有 [File System 插件](https://v2.tauri.app/plugin/file-system/)和完整的上架签名流程。

- ✅ 若未来想顺带替换桌面端 Electron,可统一技术栈
- ⚠️ 需引入 Rust 工具链;移动端生态成熟度与社区答案数量不如 Capacitor

### 路线 D:React Native / Flutter 重写(不推荐)

CodeMirror 6 是 DOM 编辑器,RN/Flutter 下必须换成 WebView 嵌入或整套编辑器重写,成本与收益完全不成比例。

## 四、落地时要处理的坑(均已核实)

1. **"任意文件夹"理念在移动端要打折**
   - iOS:应用沙盒,只能访问自己的 Documents 目录(通过文件 App 可见)+ 可选 iCloud 同步
   - Android 11+:[官方文档确认](https://capacitorjs.com/docs/apis/filesystem)`Directory.Documents` 只能访问应用自己创建的文件;要像桌面那样选任意文件夹,需要 SAF(Storage Access Framework)方案,社区有 [capacitor-scoped-storage](https://github.com/Daniele-rolli/capacitor-scoped-storage) 这类插件,或自写小插件
2. **CodeMirror 6 移动端可用但有已知小问题**(如触屏缩放后光标跳动 [codemirror/dev#1677](https://github.com/codemirror/dev/issues/1677)),Obsidian 移动端证明都可克服,建议真机早期验证
3. **iOS 上架新要求**:使用 Filesystem 插件需提供 [Apple 隐私清单 PrivacyInfo.xcprivacy](https://capacitorjs.com/docs/apis/filesystem)(文件时间戳类 API 需申报理由 C617.1)
4. **桌面专属能力需要替代或裁剪**:`electron/` 里的自动更新、deeplink、zip 导出,移动端分别对应应用商店更新、Capacitor Deep Links 插件、Share/文件导出插件
5. **移动 UI 适配是真正的工作量大头**:软键盘遮挡、安全区、安卓返回键、触屏右键菜单替代——这部分与选哪个壳无关

## 五、建议路径

1. **第一步(本周就能做)**:手机浏览器打开现有 Web 版,重点验证 CodeMirror 编辑体验 + OPFS 后端在移动端的表现——这决定后续一切
2. **第二步**:做移动端 UI 适配(触屏、视口、软键盘)
3. **第三步**:接入 Capacitor,写 `capacitorBackend.ts`(~1 个文件),iOS 配 plist 让笔记在"文件"App 可见
4. **第四步**:Android 任意文件夹需求用 SAF 插件补齐;iOS 同步需求评估 iCloud

## 六、路线 B 落地记录(2026-10-08 执行)

第一步(接入 Capacitor + Android)已经完成,与文档预估一致:UI 与业务逻辑零改动,
只新增了一个 `capacitorBackend`。

### 新增文件

| 文件 | 作用 |
| --- | --- |
| `capacitor.config.ts` | 壳配置:`com.buglan.opennote`,webDir `dist`,`androidScheme: https` |
| `src/fs/capacitorBackend.ts` | `FileSystemBackend` 的第 4 个实现(`@capacitor/filesystem`),含权限申请与原生错误中文化 |
| `src/fs/capacitorBackend.test.ts` | 契约测试(13 例,内存版插件替身,错误措辞对齐插件 `FilesystemErrors.kt`) |
| `scripts/build-mobile.mjs` | `OPENNOTE_MOBILE=1` 的 tsc + vite 构建 |

### 修改点

- `src/fs/types.ts`:`BackendKind` 新增 `"capacitor"`,`describeBackend` → 「手机文件夹」
- `src/data/workspaces.ts`:`resolveBackend` 分支 + `createMobileWorkspace()`(存进
  `Documents/OpenNote/<名字>`,创建时申请存储权限)
- `src/App.tsx` / `src/components/Sidebar.tsx`:手机上「添加文件夹」变为「新建手机笔记本」,
  图标与存储位置文案跟随 `kind`
- `vite.config.ts`:`OPENNOTE_MOBILE=1` 时**关闭 PWA Service Worker**(整包更新,旧 SW 会缓存住
  上一版资源)并**跳过 meta CSP**(Capacitor 以内联 `<script>` 注入原生桥,哈希策略会拦掉;
  WebView 只加载随包可信内容,安全层由原生壳承担)
- `package.json` 脚本:`build:mobile` / `cap:sync` / `cap:sync:web` / `open:android` / `build:apk` / `build:apk:release`
- `tsconfig.json`:include 加入 `capacitor.config.ts`

### 构建链路(Windows,本机)

1. **JDK**:Capacitor 8 的 Android 工具链要求 JDK 21(本机系统 JDK 是 17)。已把
   Temurin 21 解压到 `%USERPROFILE%\.jdks\jdk-21.0.12.1+1`,构建时以 `JAVA_HOME`
   指过去,不改系统环境变量。
2. **SDK**:compileSdk/targetSdk 36(platforms/android-36 已装),minSdk 24。
3. 命令:`pnpm build:apk`(= build:mobile → cap sync → `gradlew assembleDebug`),产物
   `android/app/build/outputs/apk/debug/app-debug.apk`。

### 已知限制(按文档第四节,状态更新)

- Android 上笔记落在**公共 Documents 的 `OpenNote/` 文件夹**(App 自己创建的文件,
  Android 11+ 无需权限即可读写;文件管理器可见)。SAF「任意文件夹」仍是后续工作。
- iOS 侧未做(需要 Mac + Xcode);接入时按文档配 `UIFileSharingEnabled` +
  `LSSupportsOpeningDocumentsInPlace`,并补 `PrivacyInfo.xcprivacy`。
- 桌面专属能力(自动更新、deeplink、zip 分享导出)未接移动等价物,按文档属后续迭代。

执行中发现并修掉的坑(都是只在真机/模拟器上才暴露的):

1. **edge-to-edge**:Android 15+/targetSdk 36 强制全屏,系统状态栏压住应用头部。
   解法是 CSS 层的新令牌 `--inset-top/bottom`(`base.css`,取 Capacitor 注入的
   `--safe-area-inset-*` 与标准 `env()` 的 max),`.app` 栅格、移动端抽屉、toast
   都让出系统条高度。
2. **meta CSP 拦掉原生桥**:Capacitor 往返回的 HTML 里注入内联 `<script>`(原生桥),
   网页版的哈希 CSP 会把它拦成白屏 → `OPENNOTE_MOBILE=1` 构建跳过 CSP 与 SW。
3. **resolveBackend 根目录错位**:最初把 `location` 直接当后端根,笔记写到
   `Documents/` 顶层而不是 `Documents/OpenNote/` 下;模拟器 `ls` 一眼定位,已修并
   补了契约测试(`capacitorWorkspaceDir` 返回值钉死带 `OpenNote/` 前缀)。

构建产物:`android/app/build/outputs/apk/debug/app-debug.apk`(8.6 MB)。
日常命令:`pnpm build:apk`(构建+同步+出包)、`pnpm open:android`(开 Android Studio)、
`pnpm cap:sync`(只同步 Web 产物)。
