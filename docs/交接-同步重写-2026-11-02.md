### ② 控制台（`42e9daf`）

### ③ GitHub 登录（`ad3a174`）

`/auth/github?mode=app|join|panel|link` + 回调（`routes/github.ts`）；进行中的授权与一次性登录码只在内存；
`POST /v1/auth/github/exchange`（码 + PKCE verifier → 设备会话）；schema v6 `identities`；
「只有已邀请 / 已绑定的」或「指定组织成员自动加入」；**不按邮箱自动绑定**；GitHub 配好后才允许关密码登录。

### ④ 加密口令与配对（`42ded9d`）

- `GET/PUT /v1/me/encryption`：服务端只存包好的 encRoot + scrypt 参数；PUT 带 `expected` 做比较并交换。
- `/v1/pairing*`：A 发 6 位码 → B 认领交公钥 → A 看到 B、核对校验码后确认 → B 拿到自己的会话 + 封好的 encRoot（只一次）。状态只在内存，10 分钟。
- `src/sync/vault.ts`：口令 scrypt（N=2¹⁵）→ wrapKey；配对 WebCrypto X25519 + HKDF + XChaCha20-Poly1305；6 位校验码防服务器中间人。

## 已知缺口（按要紧程度）

1. **加密笔记本在全新设备上下载不下来。** 加密后连文件名也是密文，`m:pathmap`（文件 ↔ 路径对照表）的编解码在
   `src/sync/crypto.ts` 里早就有，但**引擎从没接上**（`engine.ts` / `session.ts` 里没有用到）。所以第二台设备只能同步它自己也有的那些篇；
   从没见过的加密笔记会被如实跳过（`unknownDids`），设置页会说「云端有 N 篇加密笔记这台设备还认不出来」。这是重写之前就有的缺口，
   `tests/sync.e2e.test.ts` 的「全新空设备」用例钉着现状。明文笔记本不受影响。
2. **空间配额只记账不拦截**：v1 写路径不检查字节配额。控制台文案照实写了。
3. **桌面端没在运行中的 Electron 里走过**：主进程代理换服务器时的原生确认框、GitHub 深链回跳、safeStorage 记住 encRoot。
   网页端在浏览器里完整走过（见下）。
4. **GitHub 只用假的 GitHub API 测过**（`server/src/routes/github.test.ts`），没对真的 github.com 跑过一次 OAuth App。
5. 原型里有、没做的：状态栏点开的小弹层（现在直接打开设置）、配对二维码、「备份」一节（GitHub 备份仍走原来的入口）、
   附件大小上限与排除规则的设置、暂停同步、移动网络策略、版本历史与回收站、自动备份、只读维护模式、不活跃设备自动移除。
6. 对外地址、单个文件上限仍来自环境变量，控制台只读展示。`panelSecurity.ts` 里的 step-up cookie 没人用了。


2. 控制台：`http://localhost:8797/admin`（空库先看到初始化表单）。
3. 网页端经代理同源连它：

```bash
OPENNOTE_SYNC_DEV_TARGET=http://127.0.0.1:8797 pnpm dev
```

   然后在「设置 → 同步」里把服务器地址填成网页端自己的地址（`http://localhost:5173`）。
   用 `localhost` 和 `127.0.0.1` 两个地址开两个标签页，就是两台互不共享存储的「设备」，可以测配对。
