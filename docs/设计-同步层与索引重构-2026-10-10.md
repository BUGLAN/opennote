# 设计：同步层与索引重构（2026-10-10 定稿）

> 状态：**P0 已完成**（提交见 git log，全量 1071 passed / 2 skipped，`tsc --noEmit` 通过）；P1–P3 待实施。
> 范围：重做「文件同步 + 保存 + 索引」这一层；**不动**编辑器、markdown 渲染、历史快照、剪藏/收件箱/GitHub 的业务语义、文件树 UI。
> 数据变化只做**加法**（新增 `.opennote/` 文件），旧版本 App 打开新工作区不受影响。

## 0. 背景

2026-10-10 事故：用户打字途中，应用把自己的自动保存当成「外部改动」，凭空生成
`…​.conflict-2026-10-10-13-35.md` 并弹「检测到外部修改」；同时打字期间频繁整库重扫造成卡顿。
根因不在那个 bug，而在同步层模型（详见 §2）：没有「谁写的」的概念、同步粒度是整库、
账本靠每个写入者手工维护、检测与处置耦合。本设计**替换机制**而非给机制加条件。

## 1. 已锁定的决定

| # | 决定 |
|---|---|
| D1 | 用户是开发者；极简 md 笔记；文件就是真源 |
| D2 | 同一篇笔记**不会被并发写**（用户与 agent 时序错开）→ “冲突”概念整体删除 |
| D3 | **磁盘赢**：磁盘 ≠ 我们最后一次写入/读到的版本 → 重载磁盘（保光标/滚动）；若有未保存改动，先存**隐藏前像**（`.opennote/history/<笔记>/…-before-disk.md`）再重载 |
| D4 | 删除 `knownStats` / `preserveConflictCopy` / `.conflict-*.md` / “检测到外部修改”提示 |
| D5 | 保存三档：`afterDelay`（默认，**1000ms**，可配 300–5000ms）/ `onFocusChange` / `onWindowChange`；**无 off**；Ctrl+S = 立即保存；关窗前仍 flush（D11 保留） |
| D6 | 同步层 = “变更事件接口 + 各端各自实现”（见 §3） |
| D7 | 规模按指数增长设计：单事件成本 ∝ 变化文件数，与库总大小无关；元数据索引 + 正文懒加载（LRU 默认 200 篇，可配） |
| D8 | 搜索两步走：quick-open（标题/路径）先行；全文 = MiniSearch/FlexSearch + 中文 bigram，索引持久化 `.opennote/search-index.json`，watcher 增量更新 |

## 2. 核心模型与不变式

```ts
interface FileRecord { stat: { size: number; mtimeMs: number }; content: string }
fileStates: Map<Id, FileRecord>   // 取代 0.9.x 的 knownStats（P0 已收口为独立模块）
```

- **I1** 内容事实只在两处产生：`commitWrite(id)`（写成功后）、`adoptFromDisk(id)`（显式读盘后）。
  改名/移动/回收站只做**换键**。没有第三处，没有“重扫整表重灌”。
- **I2** “是不是外部改动” = **磁盘字节 ≠ record.content**。stat/mtime 只决定“要不要读”。
- **I3** 变更事件带路径；自己的写入在主进程源头过滤；刷新只作用于受影响文件/目录。
- **I4** 处置策略集中在唯一函数 `reconcileExternalChange(id)`。

```
saveNote(id):
  record = fileStates[id]; cur = stat(id)      # 唯一一次元数据调用，只决定要不要读
  if (record && differs(cur, record.stat)):
      disk = read(id)
      if (disk ≠ record.content):              # 字节判定 ⇒ 真外部改动
          if (buffer ≠ disk): writePreImage(id, buffer)   # 前像 → history，静默
          adopt(disk)                          # buffer ← disk，编辑器重载（保光标）
          fileStates[id] = { disk, cur }; return
  write(id, buffer); fileStates[id] = { buffer, stat(id) }
```

- **缺记录 ≠ 跳过检查**：缺记录 = 先读盘再定（旧「回收站/恢复静默丢数据」缺口从结构上消失）。
- **自己的保存永不误判**：写成功后 `record.content` 就是我们写的字节。

## 3. 事件接口与各端实现

| 后端 | 事件源 | 说明 |
|---|---|---|
| Electron 桌面 | @parcel/watcher（主进程） | 微去抖(~150ms)聚合 → 过滤自写路径 → bridge **按路径**下发（payload 带版本，兼容旧格式） |
| OPFS | 无 | 只有 App 自己写；I1 覆盖 |
| Capacitor | `resume`/`appStateChange` 轻比对 | 移动端无外部写者生态 |
| Web FSA | FileSystemObserver（特性检测）→ 聚焦比对 | 降级不破坏正确性 |

自写过滤：主进程在 `writeText/writeBytes/move/remove/mkdir` 登记路径（1.5s 窗口）。
它只影响“要不要刷新”，**不是**正确性账本——账本只在渲染层 `fileStates`。

派发：已知笔记 → 读+reconcile；新 .md → 入树+索引；删除 → 移出树/索引/关标签；
目录事件 → 只 `list(dir)` 差量；`.assets/**` → 忽略；单次 >50 路径 → 受影响目录差量扫描。

## 4. 保存模式

设置页新增自动保存三档（单选，默认 `afterDelay`）+ 延时输入（默认 1000ms，范围 300–5000ms）。
Ctrl+S 永远可用；关窗握手 D11 保留。

### 实施中追加的发现与修复

- **链式写入的过期捕获**：`flushAll` 会对同一篇再排一个 `flushNote`，其捕获的 buffer 是
  采纳前的旧文本；P1a 在写入前校验「捕获版本 = 当前内存版本」，过期捕获直接丢弃。
  否则「磁盘赢」采纳后会被旧快照盖回去（D08 新用例实测抓到）。
