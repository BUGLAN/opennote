# 无限画布（MVP）：磁盘格式、视口持久化与引用跟随

> 面向维护者与验证者。用户可见的一句话在 [README](../../README.md) 的特性列表里。
> 相关文件：[`src/canvas/types.ts`](../../src/canvas/types.ts)（领域类型与契约导出）、
> [`src/canvas/jsonCanvas.ts`](../../src/canvas/jsonCanvas.ts)（解析/序列化）、
> [`src/canvas/refs.ts`](../../src/canvas/refs.ts)（引用定位与改写，纯函数）、
> [`src/canvas/CanvasView.tsx`](../../src/canvas/CanvasView.tsx)（视图，只经 React.lazy 进入）、
> [`src/data/library.ts`](../../src/data/library.ts)（扫描、视口、引用跟随挂钩）、
> [`src/App.tsx`](../../src/App.tsx)（应用外壳集成）、
> [`vite.config.ts`](../../vite.config.ts)（懒加载分包与 Service Worker 预缓存）。

## 1. 这是什么

一块无限平面：文本卡片随手写，文件卡片引用库里的笔记（双击即跳转），卡片之间连线。
落盘是工作区里的普通 `.canvas` 文件 —— **JSON Canvas 1.0 格式，Obsidian 也认**。选这个
格式而不是自造一个，是因为画布文件迟早要在别的工具里被打开、被编辑：格式跟别人一致，
互操作是白得的；自造格式省下的那点设计成本，会在每一次「导出去 / 导进来」时加倍偿还。

MVP 的边界（也是本文的线索）：

- 一等公民节点是 `text` / `file` / `link` / `group`，外加本库私有扩展 `html`；其余类型原样保留、不解释；
- 视口（看到哪了）记在 `.opennote/state.json`，按画布路径为键；
- 笔记路径变了（改名 / 移动 / 恢复……），画布里的引用自动跟着改写；
- 视图（`@xyflow/react`）整体懒加载，不进启动包、不进 Service Worker 安装期预缓存。

## 2. 磁盘格式：JSON Canvas 1.0

一份画布就是根对象下的 `nodes` 与 `edges` 两个数组（缺失视为空数组，规范允许）。下面是
本应用真实落盘形态的片段 —— 一个文本卡、一个引用笔记的文件卡、一条带标签与吸附侧的边：

```json
{
  "nodes": [
    {
      "id": "n1",
      "type": "text",
      "x": 0,
      "y": 0,
      "width": 260,
      "height": 160,
      "text": "先把问题列出来，再画关系"
    },
    {
      "id": "n2",
      "type": "file",
      "x": 360,
      "y": 40,
      "width": 240,
      "height": 120,
      "file": "读书/系统设计.md"
    }
  ],
  "edges": [
    {
      "id": "e1",
      "fromNode": "n1",
      "fromSide": "right",
      "toNode": "n2",
      "toSide": "left",
      "label": "展开"
    }
  ]
}
```

序列化只有一种形态（[`serializeCanvas`](../../src/canvas/jsonCanvas.ts)）：字段序固定 ——
节点 `id,type,x,y,width,height,类型字段` 在前、未知字段按源文档插入序在后；边
`id,fromNode,fromSide,toNode,toSide,label` 在前、同理。两空格缩进，结尾恰好一个换行，
**与 Obsidian 的落盘形态一致** —— 同一个文件在两个工具间来回编辑，diff 只显示真正改过的
内容，不会因为键序抖动满屏红。

解析（[`parseCanvas`](../../src/canvas/jsonCanvas.ts)）对**任何输入都不抛异常**，因为画布
是磁盘上的普通文件，别的工具写坏的版本也必须能被打开。处置方式：

| 输入形态 | 处置 |
| --- | --- |
| JSON 语法错 / 根不是对象 | 空文档 + 一条整篇级错误（语法错带行号） |
| 单个节点缺必填字段（`id`/`type`/几何/`text`/`file`） | 跳过该节点并记错，其余照常 |
| 单条边缺 `id`/`fromNode`/`toNode` | 跳过该边并记错，其余照常 |
| 未知节点类型（`link`/`group`…） | 只要求 `id` 与 `type` 非空，**全部字段原样保留** |
| `fromSide: "wibble"` 这类越界值 | 整体挪到未知字段的位置原样输出 —— 丢字节比宽进严出更糟 |

两条硬纪律都有单测钉着（[`jsonCanvas.test.ts`](../../src/canvas/jsonCanvas.test.ts)）：
**不抛**，以及**往返幂等** —— `serializeCanvas(parseCanvas(serializeCanvas(doc)))` 与
`serializeCanvas(doc)` 逐字节相等。幂等的根基就是上面那条「已知字段在前、未知字段按源
插入序在后」的范式序：`JSON.parse` 按文档序还原键序，第二次序列化自然复现第一次。

## 3. 与规范的偏离点

本应用产出规范里的 `text` / `file` / `link` / `group` 节点，以及节点/边的 `color`、边的
`fromEnd` / `toEnd`、`file` 节点的 `subpath`。偏离规范的只有一处：

| 内容 | 说明 |
| --- | --- |
| `html` 节点（私有扩展） | `html` 字段存整段 HTML，卡内渲染走 `src/html/` 的沙箱。别家客户端会把它当未知类型原样保留 |

规范之外、别的客户端写入的类型（`embed`…）与附加属性，解析侧一律**原样保留、往返不丢**：
未知类型走 `CanvasUnknownNode`，整节点不补不删（含缺失的几何字段）。

「往返不丢数据」优先于「类型穷举」—— 别的客户端写入的新类型经过本应用读一遍再存回去，
一个字节都不能少。这条的验证方式就是 `jsonCanvas.test.ts` 里的黄金字符串用例：未知类型
节点带乱序字段进出一次，输出与输入的键序一致。

另一个容易踩的点：`file` 的路径是**工作区根相对 POSIX 路径**（即目标笔记的 id），与
Obsidian 落盘行为一致 —— 不是相对画布所在目录。外部写入的引用形态不可控（反斜杠、
`./` 前缀、前导 `/`…），一切比较都在 [`normalizeFileRef()`](../../src/canvas/refs.ts)
规范化之后做，与笔记 id 同一方言，「卡片 ↔ 笔记」才对得上号。

## 4. 视口持久化：`.opennote/state.json` 的 `canvasViewport`

「上次看到哪了」是缓存性质的状态，不值得为它发明新文件 —— 跟星标、展开目录一起住在
`state.json`，**键是画布的工作区路径**：

```json
{
  "canvasViewport": {
    "读书/看板.canvas": { "x": 10, "y": -5, "zoom": 1.25 }
  }
}
```

写入链路（[`library.ts`](../../src/data/library.ts)）：

- 画布视图挂载时读一次（`getCanvasViewport`），没有就交给 `fitView` 逻辑；
- 视口移动结束（`onMoveEnd`）后 **500ms 尾随节流**落库（`setCanvasViewport`），拖动
  过程不写盘；组件卸载时把还没落库的最后一次补上；
- 写入侧净化：`x`/`y`/`zoom` 必须是有限数、`zoom > 0`，非法输入静默丢弃 —— 视口是
  缓存，坏一次不值得弹错误打断用户；读取侧同样把坏条目丢弃、好条目保留。

键跟着文件走（与 `titleOverrides` 同一条纪律、同一批调用点）：画布改名 / 移动时
`remapIds` 把键整体替换（`moveCanvasViewport`）；画布没了（删除等）视口一起清账
（`dropCanvasViewport`）。不留指空的键，重扫时才不会让缓存反过来污染状态。

## 5. 引用跟随：路径改写挂在哪七处

`file` 卡片指向的是**路径**。路径变了引用不跟着变就是裂链 —— 用户改一次笔记名，画布
上留一片「文件已删除」，这不是用户能理解的事故。所以库层把改写挂在每一个「笔记路径
真的变了」的落点之后（[`rewriteCanvasRefs`](../../src/data/library.ts)，改写逻辑本体在
[`rewriteFileRefs`](../../src/canvas/refs.ts)）：

| # | 操作 | 挂钩位置 | 匹配方式 |
| --- | --- | --- | --- |
| 1 | 重命名笔记（`renameNote`） | `library.ts` `renameNote` 内 | 精确 |
| 2 | 移动笔记（`moveNote`） | `library.ts` `moveNote` 内 | 精确 |
| 3 | 重命名文件夹（`renameFolder`） | `library.ts` `renameFolder` 内 | 前缀（后缀保留） |
| 4 | 移动文件夹（`moveFolder`） | `library.ts` `moveFolder` 内 | 前缀 |
| 5 | 删除文件夹 · 提升到上级（`deleteFolder(promote)`） | `library.ts` `deleteFolder` 内 | 按条目；目录条目开前缀 |
| 6 | 从回收站恢复（`restoreNote`） | `library.ts` `restoreNote` 内 | 两笔：`original → 最终路径`，另防御性改写回收站路径 |
| 7 | 占位名自动改名（正文标题跟随文件名） | `library.ts` 自动改名执行体内 | 精确（与 `renameNote` 同一条纪律） |

前缀匹配**只在移动目录时开**：移动 `旧夹/` 到 `新夹/` 后，指向 `旧夹/x.md` 的卡片该跟到
`新夹/x.md`。文件级的改名/移动绝不开前缀 —— 名为 `a.md` 的文件与路径段 `a.md/`（把
文件名当目录用）互不相干，开了就是误改写。

两类**不跟随**，同样是刻意的：

- **目标进回收站不跟随**（`trashNote` 不挂钩）：节点保留失效态 —— 文件卡置灰、提示
  「文件已删除」（[`FileCard`](../../src/canvas/nodes.tsx) 的 `is-missing`）。恢复时
  （挂钩 6）才把引用落到最终路径；如果进回收站时就改写，恢复到带序号的新路径反而要
  猜「原来是谁」。
- **致命解析失败的画布跳过不动**（`error.ref` 缺省 = JSON 语法错 / 根不是对象）：宁可
  留着一条失效引用，也不把别人写坏的文件再写一遍。

改写一律走既有防抖写链路（`updateNoteContent` → refresh → markDirty → `persistNoteSoon`），
不自建第二条写通道。

## 6. 集成点速查

- **入口与分发**（[`App.tsx`](../../src/App.tsx)）：`CanvasView` 只经 `React.lazy` 进入
  （唯一的 `import("./canvas/CanvasView")`）；`Suspense` 载入态用 `.canvas-loading`；
  `activeIsCanvas` 区分活跃标签；`EditorPane` 的 tabs 过滤掉画布标签（画布视图自己接管，
  不建 CodeMirror 实例）。
- **命令**（[`appCommands.ts`](../../src/lib/appCommands.ts)）：新建画布
  （`Ctrl/⌘ + Alt + N`，与「新建笔记 `mod+N` / 新建文件夹 `mod+Shift+N`」同族第三档）、
  在画布中显示此笔记（反向定位，多张命中取 `updatedAt` 最新）、画布：缩放适配全部、
  画布：重置缩放。后三条不绑键位，可见性走 `enabled()` —— 活跃标签不是画布、或画布
  视图还没挂载（懒加载分包在路上）时，命令面板里整条不出现，不做假按钮。
- **导出/打印守卫**（`App.tsx` `exportNote` / `printNote`）：画布是 JSON Canvas 不是
  Markdown，不进 md 导出管道、不进 `window.print()`（MVP 暂无画布导出），toast 提示
  「画布暂不支持导出/打印」。
- **拖入**（`CanvasView.tsx` `onHostDrop`）：侧栏拖笔记 = 建文件卡；从系统拖图片 = 经
  `saveImageAsset` 写进共享 `.assets/`、按落点建图片卡。拖入的文件里没有图片时画布不拦，
  照旧由 `App.tsx` 的全局拖入导入接手。
- **剪贴板**（`CanvasView.tsx` 的 copy / cut / paste 监听）：走剪贴板**事件**，不拦
  `Ctrl/⌘+C/V` 的 keydown（拦了浏览器就不派发事件、读不到系统剪贴板）。复制时卡片进
  模块级内部剪贴板，同时把可读文本（`clipboardPlainText`）写进系统剪贴板；粘贴时系统
  文本与上次写入的一致 → 粘卡片本身，否则按系统内容建卡：图片 → 图片卡（同拖入），
  单独一个 http(s) 网址 → 网页卡，其余文字 → 文本卡，落在指针处。`.canvas-root` 设
  `tabIndex=-1`，点空白处焦点也留在画布里，快捷键与剪贴板事件才归画布。
- **建卡手势**：空白处双击 = 就地建文本卡并直接进编辑；从连线桩拖到空白处松手 = 建
  文本卡并连上（新卡以对侧迎向来线，见 `geometry.ts` `placeForConnectionDrop`）。
  常驻工具条五个入口齐全（卡片 / 引用笔记 / 分组 / 网页 / HTML）。
- **分组容器**：拖动分组时，几何上**完整框在里面**的卡片跟着走（`groupChildren`，拖动
  开始时算一次，与 Obsidian 同一判据，不往文件里写归属）；选中若干卡片后 `Ctrl/⌘+G`
  或右键「打包成分组」生成恰好框住它们的分组。`elevateNodesOnSelect` 关掉 —— z 序 =
  数组序，选中的分组不会盖住框里的卡。`Ctrl/⌘+A` 全选。
- **全局搜索**（`library.ts` `searchNotes`）：画布参与搜索，标题 + 卡片里的文字
  （`search.ts` `canvasPlainText`：文本卡、网址、分组名、HTML 卡纯文本、边标签；文件卡
  只是引用，不算画布写下的字），JSON 语法不进索引。
- **懒加载分包**（[`vite.config.ts`](../../vite.config.ts)）：`@xyflow/*` 被 `manualChunks`
  钉成单独 chunk，画布视图源码（`src/canvas/**` 除 `controller.ts`，加
  `src/styles/canvas.css`）只经动态 import 可达，一律落 `assets/lazy/`；workbox 的
  `globIgnores: ["**/assets/lazy/**", …]` 让它们**不进安装期预缓存**，首次用到再从网络取。
  `controller.ts` 与 `types.ts` 无三方依赖，应用外壳静态 import 它们不破坏分包。

## 7. 已知限制

### 7.1 画布不受只读锁约束

标签栏的锁按钮把笔记设为只读时（`App.tsx` 传 `locked={activeLocked && !activeIsCanvas}`），
画布标签**不生效**：画布视图没有接 `readOnly` 通道，卡片仍可编辑。只读锁的语义是「锁
编辑器不收输入」（CodeMirror 的 Compartment），画布视图不经过那条链路；补上它需要给
画布交互层做一套等价的只读态，MVP 没做。

### 7.2 文本卡是纯文本简版渲染

`text` 卡片的内容按纯文本渲染（[`TextCard`](../../src/canvas/nodes.tsx)：非编辑态直接
输出字符串），不是完整 Markdown 预览 —— 卡片里写 `**加粗**` 就显示两个星号。就地编辑是
双击进 `textarea`，blur / Esc 提交。完整 Markdown 预览需要把编辑器渲染管线接到卡片
尺寸体系里，MVP 用简版换实现成本。

### 7.3 组件交互无 DOM 自动化测试

`src/canvas/**` 的测试覆盖的是纯逻辑：解析/序列化的契约与容错（`jsonCanvas.test.ts`）、
引用匹配与改写边界（`refs.test.ts`）、id 生成（`ids.test.ts`）、控制器注册表
（`controller.test.ts`）、撤销栈（`history.test.ts`）、剪贴板（`clipboard.test.ts`）、
画布内搜索（`search.test.ts`），加上数据层的 `library.canvas.test.ts`（扫描、视口、引用跟随、
防误伤）。**画布上的真实交互**（拖卡、连线、双击编辑、右键菜单、视口恢复）没有 DOM
自动化测试，靠手动验收。这是 MVP 的测试边界，不是疏漏的借口：补 DOM 测试时优先挑
「数据进出」的链路（编辑提交 → 落盘形态、外部改名 → 卡片跟随），纯手势类收益最低。
