# 外部改动（磁盘赢）落下来时，编辑器把视口甩回文档开头

> 用户反馈（2026-10-12）：**「由 agent 修改了文件之后，滚动条往上滑出现卡住，表现为往上移动
> 移动不了、回退的情况，但是也只出现了一次。」**
>
> 实测环境：Windows / Chrome `--headless=new` / 真实 CodeMirror 6.43 扩展 + 真实样式
> 判据：`node scripts/verify-editor-geometry.cjs`（`scripts/geometry-probe` 的「不变量 4」）
> 数字全部是真实跑出来的，复现方式见文末 §5。

---

## 0. 一句话结论

**不是滚动条的问题，是「采纳磁盘版本」那一步用了整篇替换。**

`EditorPane` 的「磁盘赢」同步 effect 原来 dispatch 的是

```ts
{ changes: { from: 0, to: view.state.doc.length, insert: props.content } }
```

而 CodeMirror 在 `ViewState.update()` 里是这样记住滚动位置的：

```js
// node_modules/@codemirror/view/dist/index.js:6323-6335
let scrollAnchor = this.scrolledToBottom ? null : this.scrollAnchorAt(this.scrollOffset);
...
this.scrollAnchorPos = update.changes.mapPos(scrollAnchor.from, -1);   // ← assoc = -1
this.scrollAnchorHeight = scrollAnchor.top;
```

替换区间覆盖**全文**时，`mapPos(任何位置, -1)` 一律映射到**替换区间的起点 = 0**，而
`scrollAnchorHeight` 还是旧文档里那一行的 top（实测 3961.73px）。下一帧 `measure()` 里：

```js
// 同文件 8264-8277
let newAnchorHeight = this.viewState.lineBlockAt(scrollAnchorPos).top;   // 第 0 行 ⇒ ≈0
let diff = newAnchorHeight - scrollAnchorHeight;                        // ≈ -3961.73
...
scroll.scrollTop += diff;                                              // 整篇被拽回顶部
```

**结论：外部改动落下来的那一刻，视口被甩回文档开头**；用户正拖着滚动条往上跳的时候撞上它，
跳转就被这一次补偿改写掉 —— 看起来就是「往上移动不了、回退」。

## 1. 修复前的原始数字

判据脚本的输出（`--json` 的 `raw.externalRows`，夹具是一篇 24 000px 高、约 700 行的中文长笔记，
落点 `scrollTop = 4000`，容器高 800px）：

| 时刻 | 落点 scrollTop | 修复前落在 | 视口顶行 | 结论 |
|---|---|---|---|---|
| 改动在视口**下方**（Agent 在文末追加） | 4000 | **74** | `第 19 节` → `第 0 节` | 甩回文档开头（−3926px） |
| 改动在视口**上方**（Agent 在开头插 12 行） | 4000 | **36** | `第 19 节` → `AGENT-ABOVE-0 …` | 甩回文档开头（−3964px） |
| **正拖滚动条往上跳 1200px** 时改动落下来 | 目标 2800 | **3446** | — | 跳转被回拽 **+646px** |

> **只看像素会得到假绿。** 视口被甩回文档开头时，新的顶行同样贴在滚动容器上沿，`rect.top`
> 照样在 0 附近（第一行实测 Δ = **−29.33px**，第二行 +8.67px）—— 光比 `rect.top` 根本看不出
> 掉了 3900px。所以判据里的锚点是「**哪一行**」：行文本 + `posAtDOM` 拿到的文档位置。

---

## 2. 修法：只替换真正变了的那一段

`src/editor/externalReplace.ts` 的 `minimalReplace()` 把「旧文本 → 新文本」表示成
**公共前后缀之外**的一段改动（最终文档与整篇替换逐字相同），CodeMirror 的两条机制随即恢复成
它设计时的样子：

- **改动在视口下方** ⇒ 锚点行没被碰到 ⇒ `newAnchorHeight === scrollAnchorHeight` ⇒ `diff = 0`
  ⇒ 视口一动不动；
- **改动在视口上方** ⇒ 锚点映射到同一段内容的新位置 ⇒ `diff` 正好等于上方新增的高度 ⇒
  CM 把它补进 `scrollTop`，视口钉在同一段内容上；
- **高度表**只作废被改动覆盖的行，其余已量过的行高原样保留（整篇替换会把它们全部退回
  `HeightMapGap` 的字符比例估算 —— 那正是归档报告 §0.1 F 那条「大跨度滚动被 CM 自己改写
  `scrollTop`」的暴露面）。

修复后的同一组测量：

| 时刻 | 落点 scrollTop | 修复后落在 | 视口顶行位移 | 结论 |
|---|---|---|---|---|
| 改动在视口下方 | 4000 | **4000** | **0.00px** | 一动不动，锚点位置一个字符都没动 |
| 改动在视口上方 | 4000 | **4370** | **+0.33px** | 锚点仍是同一行；4370 − 4000 = 370.33px，正好是上方那 12 行的高度 |
| 正拖滚动条往上跳 1200px 时改动落下来 | 目标 2800 | **2800** | — | drift **0.00px** |

## 3. 判据：`scripts/geometry-probe` 的「不变量 4」

```bash
pnpm verify:geometry      # 或 node scripts/verify-editor-geometry.cjs
```

- 探针用的是**产品里那一份** `minimalReplace`（`import … from "../../src/editor/externalReplace"`），
  不是另抄一份 —— 量的是产品行为，不是探针自己的实现。
- 三个时刻：改动在下方 / 改动在上方 / 拖滚动条上跳时改动落下来。
- 判定：`|Δ 锚点 rect.top| <= 1px`，且锚点必须还是同一行（下方改动：文档位置一个字符都不许动；
  上方改动：位置必须正好后移「上方插入的那一段」的长度）。
- **判据会红**：把 applier 换回整篇替换跑一次，三行分别报
  `FAIL … 视口顶行换了一行：第 19 节 → 第 0 节`、`FAIL … → AGENT-ABOVE-0 …`、
  `FAIL … Δ = +646.00 px`（`18 passed / 3 failed`，退出码 1）。

## 4. 显式边界

改动**覆盖了视口锚点所在的字符**时（Agent 把整篇重写、或正好重写了你正在读的那一段），
锚点会映射到改动区间的起点 —— 视口落到那段新内容的最上面。这在 `minimalReplace` 的文档注释里
写明了：内容被重写之后，「同一位置」本来就没有定义；对小改动它正是想要的行为（你看到的就是被
重写的那一段）。不变量 4 覆盖的是「部分改动」（追加 / 上方插入），不覆盖整篇重写。

## 5. 怎么复现

```bash
# 判据（自己起 vite + headless Chrome，跑完自己清理）
node scripts/verify-editor-geometry.cjs --verbose

# 只把「不变量 4」的原始数据打出来
node scripts/verify-editor-geometry.cjs --json out.json && node -e "console.log(JSON.stringify(require('./out.json').raw.externalRows,null,1))"
```

前提：仓库根已 `pnpm install`、机器上有 Chrome、**5211 端口是空的**（端口上残留的旧 vite 会被
脚本复用，量出来的是旧代码 —— 见 `scripts/geometry-probe/README.md` 的「已知边界」第 8 条）。
