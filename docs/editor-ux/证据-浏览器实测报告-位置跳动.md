## 1. 探针是怎么搭的

### 1.1 挂载的是真实扩展

`probe.ts` 手写了一个最小 `EditorView`，扩展数组用的全是产品代码：

```ts
import { livePreviewField } from "../../src/editor/livePreview";
import { markdownSupport } from "../../src/editor/markdown";
import { editorSettingsField, setEditorSettings } from "../../src/editor/settings";
import { editorTheme } from "../../src/editor/theme";

const extensions = [
  editorTheme(), livePreviewField, markdownSupport,
  history(), drawSelection(),
  EditorState.allowMultipleSelections.of(true),
  EditorView.lineWrapping,
  editorSettingsField,
];
```

按任务要求**没有**用 `src/editor/setup.ts` 的 `buildEditorExtensions()`（它会拉进 `media.ts` → `../data/library`）。因此相对真实的 `EditorPane`，探针少挂了这些扩展：

| 少挂的扩展 | 是否影响布局 |
|---|---|
| `typewriterScroll`（打字机模式） | 会影响滚动，但默认关闭（`settings.typewriter === false`），所以真实默认态下等价 |
| `autocompletion` / `search` / `closeBrackets` / `bracketMatching` / `highlightSelectionMatches` / `dropCursor` | 否（只在交互时出现浮层） |
| `mediaHandlers` / `linkClickHandler` | 否（只挂事件监听） |
| `readOnlyCompartment` / `spellcheckCompartment` | 否 |
| `markdownCommands` 的 keymap | 否（本次不测快捷键编辑） |

### 1.2 样式：加载了什么，补了什么

`index.html` 链接了真实样式表 + 真实字体 + KaTeX 样式（与 `src/main.tsx` 的 import 一一对应）：

```html
<link rel="stylesheet" href="/src/styles/tokens.css" />
<link rel="stylesheet" href="/src/styles/base.css" />
<link rel="stylesheet" href="/src/styles/prose.css" />
<link rel="stylesheet" href="/src/styles/editor.css" />
```
```ts
import "@fontsource-variable/fraunces/full.css";
import "@fontsource-variable/newsreader/opsz.css";
import "@fontsource-variable/newsreader/opsz-italic.css";
import "@fontsource-variable/figtree/index.css";
import "@fontsource-variable/jetbrains-mono/index.css";
import "katex/dist/katex.min.css";
```

**只补了 `app.css` 里的 6 条外壳规则**（探针没有 React 外壳），写死在 `index.html` 的 `<style>` 里，一字不改地抄自 `src/styles/app.css:975-985`：

```css

#host.editor-host .cm-editor { height: 100%; }
```

`tokens.css` 里的 `:root` 变量**一个都没补**：`<html data-theme="paper" data-accent="seal" data-font="serif">` 已经让 `--ink / --paper / --accent / --measure / --doc-fs / --doc-lh / --font-doc / --sel / --mark / --code-bg` 全部有值。

### 1.3 一个必须踩过的坑：CM 只渲染「窗口内」的部分

CodeMirror 的 `visiblePixelRange()`（`node_modules/@codemirror/view/dist/index.js:6145-6170`）会把像素视口**同时**裁剪到 `window.innerWidth/innerHeight` **和**滚动父元素上。所以：

* 把编辑器容器（host）撑到 2600px 高没用 —— `window.innerHeight` 只有 1100 时，CM 只渲染前 1100px，文档尾部的标记段落根本不在 DOM 里（第一轮实测就撞上了：59 行只渲染了 34 行，`MARK7A/8A/9A` 全部找不到）。
* 正确做法是**把 Chrome 窗口开大**（`--window-size=1280,2900` → `innerHeight=2800`），并且每个额外探针容器用 `window.scrollTo` 挪进窗口（`probe.ts` 的 `showHost()`）。修正前后 D 场景的数字完全不同（见 §6 的说明）。

### 回答任务的问题：**CodeMirror 有没有自动补偿 scrollTop 把内容钉住？**

**有一半。** CM 确实有滚动锚定，源码在 `@codemirror/view/dist/index.js:8185-8284`（打包后是 `dist-*.js` 第 6993 行 `else scroll.scrollTop += diff;`）：

```js
// measure() 里，更新完高度表之后
let block = this.viewState.scrollAnchorAt(scrollOffset);   // 锚点 = 视口顶行
scrollAnchorPos = block.from; scrollAnchorHeight = block.top;
...
let diff = lineBlockAt(scrollAnchorPos).top - scrollAnchorHeight;
if ((diff > 1 || diff < -1) && (scroll == this.scrollDOM || this.hasFocus || ...)) {
  scroll.scrollTop += diff;      // ← 只有这一处补偿
}
```

而 `scrollAnchorAt()` 的定义（dist/index.js:6682-6685）决定了**锚点只有一个：视口顶部那一行**：

```js
scrollAnchorAt(scrollOffset) {
  let block = this.lineBlockAtHeight(scrollOffset + 8);
  return block.from >= this.viewport.from || this.viewportLines[0].top - scrollOffset > 200 ? block : this.viewportLines[0];
}
```

所以实测结论是：

* **变化块在锚点上方** → 锚点行的 top 变了 → CM 补偿 scrollTop。D1/D6 里 ΔscrollTop = **−115**，与锚点 top 的变化量完全相等（D1：987.02 → 871.89 = −115.13；D6：1045.73 → 930.61 = −115.12）。**锚点那一行被钉住了**，但**它下面的内容仍有 −32.69px 的残留** —— 补偿只认锚点一行，锚点以下的高度变化一分都不补。
  （D1 的锚点是文档第 32 行 = 表格正下方那个空行，不是隐藏行；这 −32.69px 的逐行账没有继续拆，见 §7。）
* **变化块在锚点处或锚点下方** → 锚点行 top 不变 → `diff ≈ 0` → **完全不补偿**（D2/D3/D4/D5 的 ΔscrollTop 全是 0），块下方内容按真实高度差整块跳走：**−147.69px / −13.66px / −47px**。
* `scrollIntoView: true`（D3，即真实键入/方向键路径）**不改变这个结论**：D3 与 D2 的数字一模一样（ΔscrollTop = 0，−147.69px）。因为光标本来就在视口内，`scrollIntoView` 什么也不做。

### 补充场景 —— 一次远距离跳转会被改写 **−708.63px**

用属性 setter 拦截 `scrollDOM.scrollTop`，抓到了写入者的调用栈：

```
一次大跳转 0 → 6000：实际停在 5291（差 -709px）
   scrollTop 0 → 6000        由 at bigJump (<anonymous>:26:25) 写入
   scrollTop 6000 → 5291.37  由 at EditorView.measure (/node_modules/.vite/deps/dist-*.js:6993:31) 写入
同样的距离分 100px 步进：漂移 0px，单步最大偏差 0px
同样的距离分 500px 步进：漂移 0px，单步最大偏差 0px
```

打包文件第 6993 行就是：

```js
let diff = (scrollAnchorPos < 0 ? this.viewState.heightMap.height : this.viewState.lineBlockAt(scrollAnchorPos).top)
           / this.viewState.scaleY - scrollAnchorHeight / scrollScale;
if ((diff > 1 || diff < -1) && (...)) { ... else scroll.scrollTop += diff; }
```

把 `lineBlockAt` / `scrollAnchorAt` 都打了桩，拿到了这次补偿的**完整算术**：

```
#  0 scrollAnchorAt off=6000        → line=181 top=5993.32      ← 补偿前：锚点 top（估算值）
# 15 lineBlockAt   pos=1776         → line=181 top=5284.69      ← 补偿后：同一行的真实 top
diff = 5284.69 - 5993.32 = -708.63  →  scrollTop: 6000 → 5291.37
```

为什么估算差了 708px（≈24 行）：未渲染区域在高度表里是一个 `HeightMapGap` 节点，`HeightMapGap.blockAt()`（dist/index.js:5768-5782）用**字符数比例**猜行号：

```js
if (oracle.lineWrapping) {
  let guess = offset + (height < oracle.lineHeight ? 0
      : Math.round(Math.max(0, Math.min(1, (height - top) / this.height)) * this.length));
  let line = oracle.doc.lineAt(guess), lineHeight = perLine + line.length * perChar;
  let lineTop = Math.max(top, height - lineHeight / 2);
  return new BlockInfo(line.from, line.length, lineTop, lineHeight, 0);
}
```

本文档是「长段落 + 空行」交替（markdown 的常态），字符分布极不均匀，`frac × 字符数` 猜出来的行比真实行**晚了 24 行**，于是 `scrollAnchorHeight` 是个假值，`scrollTop += diff` 就把它当成真实位移补偿掉了。

**触发条件与不触发条件（实测）**：一次跨度 ≥1000px 的跳转（滚动条拖拽/轨道点击、大纲跳转、Ctrl+End、恢复上次位置）会中招；100px / 500px 的步进式滚动**完全不中招**（漂移 0px）。这解释了为什么「用滚轮翻很顺，一拖滚动条就跳」。

## 7. 未能测出 / 说不清的项

1. **`display:none` 与 −708.63px 那个补偿的关系**：我把两者的机制都定位到了具体代码（`HeightMapGap.blockAt` 的字符比例插值 vs `measureVisibleLineHeights` 的 `getBoundingClientRect().height`），但**无法把 −708.63px 精确拆成「隐藏行贡献多少 / 字符插值贡献多少」**。可以确定的是：`display:none` 那两行最多贡献 58.72px（2×29.36），剩下的 650px 来自字符比例插值，与 `display:none` 无关。要精确拆分需要给 `@codemirror/view` 打补丁或在没有隐藏行的等价文档上重跑，本次没做。
2. **D1/D6 里那 −32.69px 的残留是怎么构成的**：能确认「补偿只认锚点一行」（ΔscrollTop 与 Δ锚点 top 精确相等），也能确认残留 = 锚点以下的高度变化量（−148 + 115.13 ≈ −32.9），但**没有逐行追出锚点以下到底哪几行变了**。要拆清楚需要给 `ViewState.measure()` 的 `heightMap.updateHeight` 打桩逐行对比，本次没做。
3. **真实 Electron 应用里的绝对数字**：探针是「真实编辑器模块 + 真实样式 + 真实字体」的独立页面，但没有 React 外壳、没有标签栏/大纲栏、没有桌面端的 `devicePixelRatio` 差异。**位移的方向与机制可以直接外推；绝对像素值会随字号/行宽/DPI 变化**（本文档用的是默认 `--doc-fs: 16.5px`、`--doc-lh: 1.78`、`--measure: 46rem`）。
4. **键入引发的跳动**（在表格/代码块里打字、回车、粘贴）没有测。本次只测了「光标移动」与「decoration 重建」两种触发方式。
5. **未验证大纲跳转/搜索结果跳转的具体实现**：我只能证明「一次性大跨度设置 scrollTop 会被 CM 改写」，没有去 `src/App.tsx` 里核对大纲面板实际用的是哪种跳转方式（如果用 `scrollIntoView` 或 `EditorView.scrollIntoView` effect，走的可能是另一条路径，`getViewport` 会额外带 `scrollTarget`，结果可能不同）。
6. **`view.docHeight` 在探针里读到 `null`**（`out/E.json` 的 `beforeScroll.docHeight`），因为它是 `ViewState` 上的 getter 而我没有从实例上取到；用 `view.contentHeight` 替代，两者关系已在 E2 里核对过。
7. **`scripts/cdp-eval.mjs --file` 有既有 bug**（`(await import("node:fs/promises")).readFile(...)` 没 await，页面收到字面量 `[object Promise]` → `SyntaxError: Unexpected identifier 'Promise'`）。我没有改这个共享脚本，而是在探针目录里放了修好的 `cdp.mjs`。
