## 1. 两条通道

| | 收件箱投递（默认） | 本地桥直传 |
| --- | --- | --- |
| 命令 | `--channel inbox` | `--channel bridge` |
| 落点 | `<笔记本>/.opennote/inbox/<条目>/` | `POST /v1/import` |
| 需要应用在运行 | **不需要**（打开后自动出现在收件箱） | 需要 |
| 需要令牌 | 不需要 | 需要（47 字符 `opn_…`） |
| 变成笔记的时机 | 用户在应用里点「导入」 | 立刻——**但**应用侧偏好会改写它，见下 |
| 回执 | 条目目录（走文件协议） | `result.status`：`created`/`appended`/`pending`/`deduped`/`duplicate`/`skipped` |

**应用侧偏好会覆盖客户端的意图**（`receive.ts` 的 `inboxPreferenceForcesPending()`）：
当 `UiSettings.importConflict === "inbox"`（**应用默认值**）且通道是外部通道
（`local-bridge` / `inpage`）且信封**没有指明落点**（`target.folder` 为空）时，
这次导入被**强制 `pending`**：跳过判定链第 2–6 步、`path` 为 `null`、不写任何笔记。
所以桥通道**不带 `--folder` 时默认只会进收件箱**——这不是失败，但**绝不能报成「已入库」**。

## 2. 收件箱条目的磁盘形状

```text
<笔记本>/.opennote/inbox/<YYYYMMDDTHHMMSS（UTC 秒级）>-<importId 前 8 位>/
  entry.json   信封（正文外置：body 为 null + bodyFile: "body.md"）
  body.md      正文（不含 `# 标题`，标题由应用写）
  state.json   { status, attempts, lastError, committedPath, updatedAt }
  assets/      附件（可选；entry.json 的 assets[].file 指向它）
```

- `entry.json` 字段：`spec` / `importId` / `title` / `body` / `bodyFile` / `source` /
  `target` / `conflict` / `tags` / `assets[]` / `client` / `enqueuedAt`。
- 附件元素：`{ name, mime, file }`，`file` 相对**条目目录**（`assets/<sha256前8>-<原名>`）。
- `state.json` 五态：`pending` / `committing` / `committed` / `failed` / `discarded`；
  保留期：`pending`·`committing` 不设期限、`committed` 24 小时、`failed` 7 天，
  `discarded` 是立即销毁（不进回收站）。
- 没有 `entry.json` 的目录**不是**条目（应用会忽略）；没有 `state.json` 按 `pending` 算。
- 总量上限 **500**，满了拒绝新投递，文案逐字：
  `收件箱已满（500 条），请先处理一些条目。`
- 同 `importId` 的第二个条目会被应用标成 `failed` + `IMP-4017`（幂等键就是身份）。

## 3. 信封字段要点（`opennote.import/v1`）

| 字段 | 必填 | 约束 |
| --- | --- | --- |
| `spec` | 是 | 精确等于 `opennote.import/v1`，否则 `IMP-4002` |
| `importId` | 是 | 8–128 个 `[A-Za-z0-9_-]`，否则 `IMP-4003` |
| `title` | 是 | 1–200 字符（UTF-16 码元）；**笔记标题写这里**，超长截断 + warning |
| `body` / `bodyFile` | 二选一 | 正文 UTF-8 ≤ 8 MiB（`IMP-4004`）；`body: ""` 允许，回 `IMP-W001` |
| `source.capturedAt` | 是 | ISO 8601 **必须含时区**（`Z` 或 `±HH:MM`），否则 `IMP-4003` |
| `source.url` | 否 | 只接受 `http(s)`；生成物用 `null`（允许） |
| `target.folder` | 否 | 工作区相对目录；拒绝对路径、`\`、`..`、含 `:` 的段 → `IMP-4008`；不存在会自动创建 |
| `target.notePath` | 否 | 只在 `append` / `overwrite` 时有效 |
| `conflict` | 否 | `new`（默认）/ `append` / `skip` / `overwrite`；**本 Skill 只用 `new`** |
| `tags` | 否 | ≤ 32 个；字符集收紧到 `[\p{L}\p{N}_\-/]`（空格、emoji 会被删掉），纯数字丢弃，回 `IMP-W007` |
| `assets[]` | 否 | ≤ 32 件、单件 ≤ 8 MiB、合计 ≤ 24 MiB；MIME 白名单：png/jpeg/gif/webp/avif/svg/bmp；SVG 必须过净化 |
| `client.name` | 否 | `chrome-extension` / `cli` / `mcp` / `share-target` / `manual` / `other`；未知归一到 `other`，仅用于日志与界面标签 |

落点/大小上限一览：HTTP 请求体 16 MiB、正文 8 MiB、标题 200 字、标签 32 个 × 32 字、
附件 32 件 × 8 MiB（合计 24 MiB）、收件箱单条 32 MiB。

## 4. 应用写出来的笔记长什么样（front-matter 8 键，固定顺序）

```text
---
source: <url，null 则整行省略>
source_title: <来源标题>
source_site: <站点>
author: <作者>
published_at: <ISO8601>
captured_at: <ISO8601>
tags: [a, b]
opennote_import_id: <importId>
---

# <title>

<body>
```

- **除 `tags` 外全是惰性键**：应用不会因为 front-matter 里有 URL 就做来源索引，
  也不会用 `opennote_import_id` 做去重（去重靠 `.opennote/import-index.json`）。
- 标题必须由应用写成正文首个 H1：写 `title:` 键**不改变**笔记标题。
- 正文里的 `#tag` 也会被收集成标签（不只 front-matter）。
- 源文档自己的 front-matter **默认被剥掉**（否则它会作为普通文本出现在 `# 标题` 之后）。
  确实要留用 `--keep-front-matter`，但要清楚：那一段会成为正文里的字面文本，
  而**不会**成为笔记的 front-matter（笔记的 front-matter 只由应用生成）。

## 5. 去重判定链（从上到下第一个命中者胜出）

| 步 | 条件 | 结果 |
| --- | --- | --- |
| 1 | 同一 `importId` | `deduped`，**完全不写盘**，返回首次落点（首次落点是收件箱时给 `inboxId`、`path` 为 null） |
| 2 | 同 `source.url` 且正文哈希相同 | `duplicate`，不追加 |
| 3 | 同 URL、正文不同、`selection: true` | `appended`（追加） |
| 4 | 同 URL、正文不同、整页 | 进收件箱 `pending` |
| 5 | 仅正文哈希相同、URL 不同 | 视为两条独立笔记 |
| 6 | 都不命中 | `created` |

**本脚本场景下的三条重要推论**（照抄判定链会踩坑）：

1. **第 3/4 步不会发生在本技能上**：它们只在客户端**没有显式传** `conflict` 时生效
   （`receive.ts:427,446,462`），而本脚本**永远显式传 `conflict: "new"`**
   （为了「绝不追加、绝不覆盖」）。同 URL 不同正文 → 走第 6 步 `created`。
2. **`url: null` 被当作「同一个空来源」**（`importLog.ts` 的 sourceHash 对空串取哈希）。
   而 Agent 产出默认就是 `url: null` ⇒ **两篇正文完全相同、只有标题不同的文档，
   第二篇会命中第 2 步 `duplicate`（不新建、不写盘）**。这是刻意的（内容相同就别存两份），
   但要如实告诉用户「第二篇没进去，因为正文与已入库的那篇逐字相同」。
3. **第 1 步优先于上面所有步骤**，也优先于收件箱：同 `importId` 重投永远不写盘。

推论：**不要用正文哈希当 importId**（那会把「同一内容再剪一次」误报成「同一次投递」），
也不要把两篇内容合并成一条。

## 6. 错误码 / 警告码与逐字文案

| 码 | 逐字用户文案 | 处置 |
| --- | --- | --- |
| `IMP-1001` | 本地接口未开启。请在 Opennote 的「设置 · 文件 · 导入与接口」里开启，然后重试。 | 让用户开接口 |
| `IMP-1004` | 本地接口没有及时响应。请确认 Opennote 正在运行。 | 重试一次 |
| `IMP-2001` | 这个客户端还没有配置访问令牌。请在 Opennote 的「导入与接口」里复制令牌，粘贴到客户端。 | 配置令牌，**不要重试** |
| `IMP-2002` | 访问令牌不正确或已失效。重新生成令牌后，请在客户端里更新。 | 重新复制令牌，**不要重试** |
| `IMP-4002` | 这个客户端版本太旧（或太新），请更新后再试。 | 检查 `spec` |
| `IMP-4003` | 导入内容缺少必要信息（标题、来源时间或地址），请重试。 | 补 `title` / `source.capturedAt` |
| `IMP-4004` | 正文太长了（超过 8 MB），请分次导入。 | 拆分 |
| `IMP-4005` | 这次剪藏的内容太大（超过 16 MB），请分次导入或去掉图片。 | 拆分 / 减附件 |
| `IMP-4006` | Opennote 没有在运行。请先打开 Opennote，再试一次。 | 起应用或用收件箱通道 |
| `IMP-4007` | Opennote 里还没有打开笔记本文件夹。请在 Opennote 左侧选一个文件夹，或新建一个，再试一次。 | 打开笔记本 / 给 `--workspace` |
| `IMP-4008` | 目标目录不合法：不能使用 ..、绝对路径或系统保留字符。 | 修 `--folder` |
| `IMP-4010` | 这个目录里同名文件太多了，请换一个目录或改标题。 | 换标题/目录 |
| `IMP-4011` | 「追加」的目标不存在，已改为新建一篇。 | 正常（已降级） |
| `IMP-4012` | 有一个附件无法导入（格式不支持或太大）。 | 换附件格式/压小 |
| `IMP-4013` | 附件太多或太大，请减少后用重新剪藏。（收件箱满时用 `收件箱已满（500 条），请先处理一些条目。`） | 减附件 / 清收件箱 |
| `IMP-4014` | 导入时出现了内部错误，已记录日志。请重试一次。 | 重试一次 |
| `IMP-4015` | 导入太频繁了，请稍等几秒再试。 | 等 `Retry-After` |
| `IMP-4017` | 没有找到这条导入记录。（同 id 重复投递时用来标第二条） | 幂等，正常 |
| `IMP-4020` | 上一次导入还在进行中，请稍候重试。 | 稍后重试 |
| `IMP-5001` | 写入笔记失败，磁盘可能已满或没有权限。原内容没有丢失。 | 重试一次 |

警告码（逐字，`electron/bridge.cjs`）：`IMP-W001` 正文为空，只写入了标题。 / `IMP-W002` 正文里有未声明的本地附件引用，已原样保留。 /
`IMP-W003` 没找到要追加的笔记，已新建一篇。 / `IMP-W004` 目标笔记有外部改动，已另存为新文件以免覆盖。 /
`IMP-W005` 幂等索引写入失败，重复导入可能产生副本。 / `IMP-W006` 网页发布时间无法识别，已忽略。 /
`IMP-W007` 部分标签不符合规则，已忽略。 / `IMP-W008` 本次追加没有留下可回退的前像，撤销将只把笔记移入回收站。

## 7. 明确不做的事（硬红线）

- 不默认覆盖、不静默覆盖、自动化客户端永不覆盖（`overwrite` 四道闸门，本 Skill 永不使用）。
- 不代用户抓网页（应用不会对 `source.url` 发起任何请求）。
- 不读取笔记正文、不做全文搜索、不删除/移动笔记（导入能力只写不读）。
- 不把 `.opennote/` 当正文：删掉它只损失去重与撤销能力，不损失正文。
- 桥**绝不**返回工作区绝对路径（这是安全设计，不是缺失）；定位笔记本要靠
  桥的笔记本名 + `recent-workspaces.json` 同名匹配，或用户显式给路径。
