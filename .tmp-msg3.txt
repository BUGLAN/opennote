## 图片下载（用户新需求）
设计冻结（用户确认）：图片跟笔记走（<目录>/foo.md -> <目录>/foo.assets/）、
插件选项默认关、正文写相对路径。

- 接收端：资产落 <笔记目录>/<笔记名>.assets/；正文引用改写成相对路径；
  两趟扫描（原三次 split/join 会把已改写的 foo.assets/x.png 再匹配成
  foo.foo.assets/x.png）；重名不静默覆盖（读回比字节 -> 复用或 -2 去重，
  用 -2 不用空格，因为引用里空格会截断链接）；硬闸 = sanitizeName +
  assertSafeRelative + 比对 parentPath(落点) === 附件目录（joinPath 会把 ..
  归一化，纯词法校验看不出悄悄写到目录外）；撤销时资产与正文一致
  （旧图不删、本次新增才删、清不掉的如实说明）
- 收件箱：assets[].file 就地解析、绝不转交（修掉一个真缺陷 —— 收件箱按
  「条目目录」解释该字段、接收端按「工作区根」解释，越界时转交 = 语义漂移
  + 跨读）；缺文件/越界/畸形一律 IMP-4012 如实失败；入库成功后清掉暂存；
  幂等；面板不再显示 0 B 的失真大小
- 两条裁定：删除/搬迁必须连带资产目录（restoreNote 是同一段逻辑的反方向，
  两个方向一起改 —— 只修一半等于没修）；三路统一到同一个 assetsDirFor，
  旧数据不迁移（路径已写在 Markdown 里，迁移风险大于收益）
- 红证明：H1 不迁移旧数据（顺手迁移 -> 2 红）、H2 撤销不误删旧图（1 红）、
  H3 派生边界 11 条字面量 + 3 条不变量（退回公共 assets -> 13 红）

态被节流，消息根本没发出去，工具驱动不了该路径。有效证据来自用户人工，
不是机器；边界写入 README 13.1 与工具头部，不是失败也不是已机器验证。
